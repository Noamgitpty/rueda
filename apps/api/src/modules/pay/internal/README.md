# Port `PaymentProvider` (US-019 ; 17 §2.8, §4.3, §4.4, §6.5 ; ADR-032, ADR-045, ADR-059)

Aucun code métier ne connaît un PSP. Jusqu'au lot C, seul l'adaptateur **FAKE** existe, et il n'est **jamais actif en production** (C19). Tout passe par l'index public (`index.ts`).

## FAKE (répertoire `testing/`, tests seulement)

`testing/` est exclu de `tsconfig.build.json` et n'est exporté par aucun index ; `@rueda/fake-adapters` (PSP simulé) n'est qu'une dépendance de développement (`internal/production-isolation.test.ts`).

- `fake-payment-provider.ts` : adaptateur du port au-dessus de `FakePsp` (mêmes contrôles qu'un connecteur réel) ;
- `contract.ts` : **suite de contrat** du port, à rejouer telle quelle sur le connecteur réel en bac à sable (US-601) ;
- `fake-stack.ts`, `memory-stores.ts` : montage complet et magasins en mémoire (mêmes règles que les commandes SQL) ;
- mode hostile scriptable : délais dépassés avant ou après succès, réponses illisibles, panne, refus (dont « ne pas réessayer »), webhooks en double, hors d'ordre, retardés, perdus, rejoués, ordres Yappy de 300 s, liens réutilisables, capacités absentes ou seulement `DOCUMENTED`.
