# Passation US-048 — Coquille web mobile-first et PWA installable (2026-11-03, agent front-end, claude-opus-5-5)

Branche `story/US-048-coquille-pwa`, partie de `origin/main` (796d48c), worktree `.claude/worktrees/us-048-dev`. **Statut : EN REVUE.** Revues exigées (`review-requirements.json`) : **code** et **ux** (Revue design : OUI), sur un autre modèle que l'auteur. Décision : ADR-072 (PROPOSÉ). Aucune migration.

- **Fait** (critères de 19 US-048) :
  - **360 px, aucun défilement horizontal, cibles ≥ 44 px** : coquille `app/(app)/` (lien d'évitement, en-tête collant en verre, marque, choix de langue sans JavaScript, région live du réseau) et écrans accueil et « Sin conexión ». Mesuré par `apps/web/scripts/shell-check.mjs` (protocole DevTools de Chrome, 360 × 780, quatre langues, clair et sombre, menu de langue ouvert, bandeau hors ligne) : largeur 360/360 partout, aucune cible sous 44 px (le thème réserve 48 px). Captures : `docs/design/US-048/*.png` (10).
  - **Manifeste depuis le thème (US-034)** : `/manifest.webmanifest` (nom, description dans la langue, `theme_color`, `background_color`, icônes) et icônes PNG dessinées depuis le logo et les couleurs (`/icons/*.png`, `next/og`, maskable dans la zone sûre). Source : `brand-source.ts`, qui lit `GET /brand` si `WEB_BRAND_API_URL` est définie (document revalidé, CSS recompilé ici, cache 30 s, délai 1,5 s), sinon le thème embarqué ; fail-closed. Le report « brancher le site sur `GET /brand` » de `RESUME_HERE.md` (US-120 / US-032) est donc **fait pour `apps/web`** (pas pour le back-office). **Installable** : `Page.getInstallabilityErrors` de Chrome vide. iOS : `apple-touch-icon`, titre, manifeste (campagne réelle : protocole US-026).
  - **Perte de réseau** : service worker `/sw.js` (pages réseau seulement, jamais en cache ; écran `/offline` pré-chargé rendu à la place, avec reprise ; ressources de build en cache) ; vérifié avec le **vrai service worker** dans Chrome (capture `sw-hors-ligne-es-360.png`) et par un test qui exécute le script contre des caches simulés.
  - **Quatre langues** : 18 clés en es / en / fr / pt (`web.shell.*`, `web.offline.*`, `common.offline.restored`, et les `web.s01.*` de l'accueil reprises **mot pour mot** de 10b §4.3, pt traduit) ; `CATALOG_VERSION` 9. Le nom affiché n'est plus `{brand_name}` : c'est la marque du thème (Kmino).
  - **Mouvement réduit** : entrée de l'accueil, tracé du _camino_ (700 ms, une fois) et panneau de langue arrêtés par `prefers-reduced-motion` (lint du mouvement vert).
  - Docs : README d'`apps/web` (section « Coquille et PWA », variable `WEB_BRAND_API_URL`), `.env.example`, ADR-072, journal de session.

- **Pièges / hypothèses** :
  - `packages/design-tokens/test/lint.test.ts` lit `apps/web/app/home.module.css` (classe `.tagline`) et `apps/web/app/home-content.tsx` (balise `</main>`) : ne pas les déplacer. D'où : chaque écran rend son `<main>` ; l'accueil reste hors du dossier `(app)`, importé par `app/(app)/page.tsx`.
  - Satori (`next/og`) plante sur une clé de style `undefined` ; le service worker n'hérite pas des en-têtes de la page (langue par cookie dans le contrôle).
  - Chrome sans interface sous Windows impose une fenêtre d'au moins 500 px : `--window-size=360` ne suffit pas, d'où l'émulation par le protocole DevTools.
  - Le service worker n'est enregistré qu'en build de production (pas de cache périmé en `next dev`).
  - Cible tactile : le thème donne 48 px (`size.touchTarget`), au-dessus des 44 px du critère.
