# Passation US-008 — Outbox transactionnelle, événements et tâches planifiées (2026-11-03, agent back-end, claude-opus-5-5)

Branche `story/US-008-outbox-evenements`, worktree `.claude/worktrees/us-008-dev`, PR en brouillon. **Statut : EN REVUE** (code, architecture, QA ; sécurité aussi, car `packages/db/` est touché).

- **Fait** :
  - Migrations `0100_outbox_tables`, `0101_outbox_functions`, `0102_outbox_grants` (plage réservée 0100 à 0149) : `core.outbox_outbox_event`, `outbox_scheduled_job`, `outbox_inbox_receipt`, `outbox_dead_letter`, RLS `ENABLE` + `FORCE`, `platform.uuid_v7()`, fonctions `core.outbox_*` `SECURITY INVOKER`, politiques par travailleur (une file = un `app.worker_name`).
  - Module BUS (`apps/api/src/modules/bus`) : `publishEvent`, `BusRegistry`, `OutboxRelay`, `JobRunner`, `scheduleJob`, `workerTransactions`, port `Alerter` (`LogAlerter`), README.
  - Critère 1 (transaction annulée ⇒ aucun événement) : `packages/db/test/l0/outbox-idempotence.test.ts` et `apps/api/test/int/bus.int.test.ts`.
  - Critère 2 (rejeu ⇒ `inbox_receipt` empêche le double traitement ; 5 échecs ⇒ `dead_letter` avec alerte) : mêmes fichiers, plus réception concurrente, bail expiré, cloisonnement des files.
  - ADR-050 (PROPOSÉ) : la file `scheduled_job` est portée en SQL sous RLS, pg-boss différé (incompatible avec RLS FORCE, `platform.now()` et les rôles de production).
- **Reste** :
  1. Revues ; report d'ADR-050 dans 17 §8.1 et de la ligne `scheduled_job` de 17 (orchestrateur).
  2. Processus `worker.ts` (boucles du relais et des files, pool) : US-003 (secrets, déploiement).
  3. Purge 90 j (outbox, reçus) et rejeu console des lettres mortes (ADMIN, journalisé) : stories à venir.
  4. Valeurs PROPOSÉES à transformer en paramètres 17 §7.2 si besoin : attente de base 30 s, bail 300 s, lots 100 / 10.
- **Prochaine commande exacte** : `pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test:unit`, puis `gh pr checks <PR>` (job « base de données » : la CI fait foi, ADR-043).
- **Pièges / hypothèses** :
  - **Numérotation** : l'exécuteur (`src/migrate.ts`) accepte un trou mais **refuse une migration plus ancienne que la dernière appliquée**. Si 0100 est appliquée dans un environnement persistant avant 0008 / 0009 (US-013), ces dernières seront refusées. Sans effet en CI (bases jetables) ; à trancher avant le premier environnement persistant. Non contourné.
  - `avl-schema.test.ts` : liste des tables `core` limitée hors `outbox_*`, politiques limitées à `booking|payment` (même modification que la branche US-013 : fusion sans conflit attendue).
  - `apps/api` a désormais un `test:int` (banc `@rueda/db`, exports `./testing/global-setup` et `./testing/setup-l0-05`) ; `turbo.json` : `test:int` dépend de `^test:int` (séries en file sur une instance native).
  - `last_error` et les alertes ne gardent qu'un code (SQLSTATE ou nom de classe), jamais le message.
  - `aggregate_id` est un `uuid` ; `country_code` est nullable (format seulement).
- **Paramètres créés (17 §7.2)** : aucun (valeurs PROPOSÉES en options du code, ADR-050). **Entités / migrations** : ci-dessus ; spécification : 5 tentatives (17 §4.2).
