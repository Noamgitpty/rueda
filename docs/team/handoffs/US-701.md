# Passation US-701 — Caution de la plateforme et fenêtre de rétention

- **Branche** : `story/US-701-caution-plateforme` ; agent de story argent, claude-opus-5-5 ; ADR-169 (PROPOSÉ).
- **Numéros pris** : migration `0146_payment_deposit_hold` (suivante de `main` au moment de pousser ; à renuméroter à chaque fusion de `main`), fixture `9945_test_us701_deposit_hold_fixtures.sql`, catalogue **v85**, ADR-169, GL-46.

## Livré

1. **`core.payment_deposit_hold`** (0146) : une décision par hold, figée avant le paiement ; `NOT_REQUIRED` ⇔ aucun déclencheur ⇔ montant 0 ; `REFUSED` jamais écrit (un checkout refusé n'écrit aucune ligne) ; `triggers` / `params_snapshot` [C2] ; garde et transitions ; aucun droit applicatif direct. Commandes de cmd_hold_owner : lecture du voyageur (sans [C2]), écriture unique revérifiée (montant = `deposit_amount[pays][classe]`, aucune `NOT_REQUIRED` sur une classe déclencheur ou inconnue, rail (b) fermé par `funds_holding_enabled`), file et transitions de la minuterie (`payment_command`).
2. **Checkout** (AVL) : `GET …/payment` rend `payment.deposit` ; `POST …/payment` applique la porte avant T1 (409 `DEPOSIT_RAIL_UNAVAILABLE` / `DEPOSIT_PARAM_MISSING`, aucune écriture ni ordre) ; OpenAPI (`CheckoutDeposit`, codes 409).
3. **S05** : aucune caution / montant, blocage temporaire, libération au plus tard / refus (`assertive`) avec les jours possibles et une sortie vers la recherche ; aucun « Pagar » si la caution est impossible. Textes `web.deposit.none`, `common.payment.depositUnavailable` (es, en, fr, pt-BR).
4. **Minuterie** `deposit_timer` (PAY, 60 s) : ré-autorisation par le port ; refusée ⇒ décision avancée à expiration − 2 h, alerte `DEPOSIT_REAUTH_FAILED`, aucun débit ; en cours ou inconnue ⇒ rien, même clé ensuite.
5. **Fonctions pures** : `evaluateDepositCheckout`, `planDepositSchedule` (T57 : décision à fin + 70 h), `depositScheduleAfterReauth`.
