- **Fait** :
  - **Critère 1** (OTP au-delà de la limite) : `AbuseGuard.checkCostlySend` / `guardedSend` (RISK) : limite par numéro **et** par IP à l'heure, puis plafond SMS du pays ; au-delà `429 RATE_LIMITED` avec délai de reprise, `send` jamais appelé, refus journalisé (`risk_abuse_event`) ; code distinct d'`OTP_LOCKED`. Même règle pour les e-mails coûteux (adresse et IP).
  - **Fail-closed** : compteur, pays ou paramètre indisponible ⇒ `503 RATE_LIMIT_UNAVAILABLE` (PROPOSÉ), aucun envoi.
  - **Critère 2** (plafond SMS du pays) : port `SmsBudget` dans NTF, adaptateur `ntfSmsBudget` dans RISK ; `core.risk_cmd_sms_reserve` compte par **jour local** du pays ; gabarit `critical` (confirmation, annulation, retard de trip ; PROPOSÉ) toujours envoyé et compté ; non critique refusé (`SMS_DAILY_CAP`), repli e-mail s'il existe ; alerte `notification.sms_cap.reached` au premier refus du jour.
  - **Critère 3** (recherche, devis, API) : garde global par IP (`APP_GUARD`, monté en premier) et intercepteur global par compte (`APP_INTERCEPTOR`, après `SessionGuard`) ; portée par préfixe (`/search`, `/quote(s)`, `/webhooks` à limite large, sinon `api`) ; `429 RATE_LIMITED` + `Retry-After` + `values.retryAfterS` ; compteurs par client ; base indisponible ⇒ repli en mémoire (même seuil).
  - **Critère 4** (robots) : signaux `NO_BROWSER_HEADERS`, `REGULAR_RHYTHM`, `SIGNUP_BURST` ; un signal ⇒ ralenti (poids `rate_limit_bot_weight`) ; rafale ou deux signaux ⇒ défi exigé (`X-Bot-Challenge`, port `BotChallengePort`, `FakeBotChallenge` en test, `UnavailableBotChallenge` en production ⇒ `403 BOT_CHALLENGE_REQUIRED`). Tableau de sécurité : `core.risk_staff_abuse_board` + `GET /console/security/abuse` (SUP), permission `security.read_abuse` (ADMIN, SUPERADMIN), TOTP, refus journalisés.
