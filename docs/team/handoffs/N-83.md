# Passation N-83 — Classe de valeur attribuée à la publication d'un véhicule non classé (suite de N-101 et N-115 ; US-113, US-118) (2026-11-18, agent données, claude-opus-5-5)

- **Branche** : `story/US-113-US-118-classe-valeur`, partie d'`origin/main` (bddd814b) ; worktree `../wt/classe-valeur`.
- **PR** : #229, en brouillon.
- **Statut** : EN REVUE. Revues exigées (`check-story-reviews.mjs`) : architecture, code, qa, sécurité (SECURITY DEFINER, RLS : autre modèle que l'auteur). Suggestion : une revue argent, car la classe déclenche la caution `LUXE` (BR-PAY-06) et l'âge par classe.
- **Décision** : ADR-159 (PROPOSÉ).

## Fait

- **Règle** (ADR-159) : à la publication, un véhicule sans classe reçoit la classe de sa variante (`CATALOG`), sinon d'une règle de modèle ou de marque (`MODEL_RULE`, `MAKE_RULE`), sinon le défaut du pays (`COUNTRY_DEFAULT`). Rien ne la donne : aucune classe, jamais couvert (comme avant).
- **Migration 0134** (générée par `seed-sql.ts`, `POST_SEED_PARAMS`) : `vehicle_default_value_class` (ENUM, `BLOCK`), **STANDARD PROPOSÉ** en PA et en PY ; entrée de `country-data-allowlist.json`.
- **Migration 0135** :
  - table `core.catalog_value_class_rule`, graine PROPOSÉE sans code pays (marques de luxe en LUXE, marques premium en PREMIUM, modèles de valeur haute relevés ; aucune règle sous le défaut) ;
  - colonnes `catalog_vehicle.value_class_source` et `value_class_rule_id` ;
  - `core.catalog_value_class_resolve` et `core.catalog_vehicle_assign_value_class` (INVOKER, migrator, EXECUTE `catalog_cmd_owner`) ;
  - déclencheur `catalog_vehicle_value_class_follow` (rattachement par l'ops d'un véhicule déjà classé) ;
  - `core.catalog_cmd_submit_listing` : corps de 0084 recopié, une étape ajoutée (marquée N-83) après les photos.
- **Interrupteurs** : aucun touché ; `INSURER_CONTRACT_INACTIVE` toujours rendu sans contrat ni interrupteur (prouvé).
- **Tests** :
  - `l0-n83-value-class.test.ts` (PA, PY, `app_api`, transactions annulées) : Geely Coolray de la douane jusqu'à LISTED et la fiche publique ; contrat fermé ; défaut paramétré ; huit variantes premium ou de luxe (douane et v1, règle la plus précise) ; cinq saisies hors catalogue ; Porsche refusée par un contrat limité à STANDARD, publiée avec un contrat de toutes les classes ; véhicule déjà classé jamais recalculé ; Hilux v1 au défaut ; MERGE par l'ops (classé ⇒ recalculé, jamais publié ⇒ inchangé) ;
  - fixture `9944_test_n83_value_class_fixtures.sql`.
- **Test de sécurité modifié** : `l0-n101-catalogue-pa.test.ts`, justification ligne à ligne :
  - l'attendu `VEHICLE_NOT_COVERED` pour une variante sans classe est retiré : c'est exactement le comportement que N-83 change (la classe est maintenant attribuée) ;
  - la fiche publique reste vide après la première publication (assertion gardée) ;
  - la pose manuelle de la classe (« TÉMOIN ») est retirée : la classe vient de la règle ;
  - les attendus suivants (`VEHICLE_ELIGIBILITY_REQUIRED`, puis `LISTED` et la fiche publique) sont inchangés.
  - Le refus d'une classe non couverte reste prouvé par `l0-us108` (inchangé) et par `l0-n83` (Porsche et contrat STANDARD).
- **Docs** : ADR-159, README CAT (et sa ligne périmée sur le marché de la douane, N-115) et `packages/db`, `changelog.d/US-113-US-118-classe-valeur.md`, paramètre dans `params.json`, `COMME_TURO.md`, `POUR_LE_FONDATEUR.md` §3, `GO_LIVE_CHECKLIST.md` GL-35, `authorization-matrix.json`, `personal-data-inventory.json`.
