## Pièges

- Le catalogue des actions n'admet aucun chiffre dans une valeur (`^[A-Za-z][A-Za-z_]{0,31}$`) : `LICENSE_NOT_UPLOADED` est traduit en `LICENSE_NOT_UPLOADED_1H` par la commande liée.
- La commande liée ne voit pas les pièces de l'action (le cadre écrit `manual_action` APRÈS l'appel) : la preuve est lue par le travailleur, une fois l'action validée.
- `SELECT … FOR UPDATE` du trip sous la console échouerait (politique `cmd_trip_upd` réservée à `trip_lifecycle`) : la commande liée prend les verrous consultatifs voyageur puis véhicule, puis relit l'état.
- Les commandes d'argent gardent leur contrôle de travailleur : le processeur change `app.worker_name` dans la transaction (`set_config(…, true)`), comme les preuves d'US-224.
- Ligne des dérogations expand / contract : le NUMÉRO de ligne des deux `UPDATE` du catalogue est dans `expand-contract-allowlist.json` (214, 219) ; toute ligne ajoutée avant eux dans la migration les décale.
- Les instants des preuves L0 sont virtuels (2031) ; la session de staff est ouverte à l'instant virtuel (`test_fixture.iam_open_elevated_session`, comme US-108).

- `@rueda/db` n'est **pas** dans l'image de production de l'API (`ERR_MODULE_NOT_FOUND` aux jobs « déploiement local » et « rotation des secrets », run 44027545597) : le processeur classe les erreurs de la base par SQLSTATE et nom de contrainte (code garé = contrainte en majuscules, ex. `OPERATION_SETTLEMENT_FIN_REVIEW`), sans `translateDbError`.
- `schema.md` recopié du log du job « base de données » : les lignes de vitest y sont entrelacées, parfois au milieu d'une ligne du document (ex. `platform_advance_trip_country_fk`) : recoller la ligne coupée.

- Un compte PSP `ACTIVE` validé dans un test bloque tous les autres fichiers (`psp_account_one_active`, run 44029929295) : `l0-us215-trip-cancellation` réutilise le compte partagé de la fixture 9800 (`test_fixture.us024_psp_account`) et tourne dans le groupe isolé (`vitest.l0.config.ts`), comme `l0-us224-refund-race`.
- La répétition du déploiement (`scripts/deploy/rehearsal.sh`) vérifie la liste exacte des files du travailleur : `trip_lifecycle` ajoutée (dix-sept files).

- Depuis US-224b (0123, ADR-147), un ordre REFUND naît d'une instance `PLANNED` (`core.payment_cmd_plan_refund`, `PgRefundPlanner.plan`, rail `NATIVE_PARTIAL`) : un REFUND forgé sans instance est refusé. Le processeur et les preuves L0 passent par cette commande ; l'envoi au PSP (`submit`) reste au service d'US-224. `advance_decision_required` gare la demande `FIN_REVIEW`.
- Les preuves de ce fichier isolé ne valident aucune clé de preuve TOTP (piège d'US-224b) : staff créé sans facteur, session élevée ouverte à l'instant virtuel par la fixture 9650.
