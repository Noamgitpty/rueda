- **Pièges / hypothèses** :
  - `AppData\Local\hermes\node` contient un Node v22.23.2 qui peut passer en tête du PATH.
  - En Git Bash, `$APPDATA` vaut `C:\…` : `"$APPDATA/npm"` casse le lanceur pnpm (`Cannot find module 'C:\Program Files\Git\Users\…\pnpm.cjs'`). Écrire le chemin Unix.
  - Node 26 importe directement les `.ts` de `packages/config/eslint/`, `packages/config/sql-clock/` et `apps/api/src/modules/dependency-graph.ts`. Ces fichiers doivent rester en syntaxe effaçable : pas d'`enum`, pas de `namespace`, pas de propriétés de paramètre. Les imports y portent l'extension `.ts`, sauf dans `apps/api`, qui importe en `.js` (compilé par `tsc`).
  - Vite/Vitest résout les `extends` de tsconfig sans suivre les liens symboliques. C'est pourquoi la base stricte vit dans `packages/config/tsconfig/base.json` et que `tsconfig.base.json` racine l'étend : ne pas inverser.
  - TypeScript reste en **6.0.3** : `typescript-eslint` 8.71 exige `<6.1.0`, alors que TypeScript 7.0.2 existe.
  - **Limites de la règle de frontières** (revue code #5). Formes couvertes : `import`, `export … from`, `import()` avec un littéral ou un gabarit sans expression, `require()`, `require.resolve()`, un alias de `createRequire` (`const req = createRequire(…)`) et `createRequire(…)('…')`.

    Formes **non couvertes** :
    - `import(variable)` et les gabarits avec expression (spécificateur calculé) ;
    - un `createRequire` réaffecté ou passé en paramètre ;
    - les alias de chemin (`paths` de tsconfig) et les paquets nus (`@rueda/api/...`) : il n'y en a aucun aujourd'hui, et la règle ne voit que les imports relatifs ; à adapter si l'un d'eux apparaît.

    Ces cas relèvent de la revue d'architecture.

  - Le lint SQL analyse le contenu des chaînes dollar comme du code. Un `$$now()$$` utilisé comme simple littéral serait donc signalé (faux positif volontaire).
  - Hypothèse « socle implicite » : 17 ne dit pas en toutes lettres que tous les modules dépendent de CFG, AUD et BUS. Il dit (§2.1) que le socle « ne dépend de personne », ce qui garantit l'absence de cycle. L'ajout implicite vaut donc pour les modules hors socle seulement.
  - Corrigé après la revue d'architecture #2 : CFG → BUS et AUD → BUS sont autorisés, puisque ces deux modules publient par l'outbox. BUS reste sans dépendance. 17 §2.1 est à reporter en « le socle ne dépend que de BUS » (orchestrateur).
  - Lint SQL (revue code #4) : `"now"()`, `"pg_catalog"."now"()` et `timeofday()` sont maintenant détectés. Un identifiant entre guillemets suivi de `(` ou de `.` reste visible pour le scanner. Limite restante : un commentaire placé entre `"now"` et `(` masque l'appel.
  - Travailleur (revue architecture #10) : `worker.ts` initialise le contexte puis s'arrête, ce qui est voulu avant US-008. Les gestionnaires pg-boss et l'outbox seront enregistrés **au travailleur seulement**, par un module réservé avec la connexion `app_worker`, jamais par l'API. La consigne est en commentaire dans `worker.ts`.
  - Écart : SUP « tous (lecture) » est codé comme tous sauf RPT, parce que RPT lit tout, SUP compris, et que l'inverse ferait un cycle.
  - Écart : 17 §10 point 3 (Bêta) prévoit une seule application Next.js, le back-office étant le même code sur un domaine distinct. La consigne de US-001 et 17 §6.1 demandent `apps/backoffice` séparé, qui a été créé. Noté dans ADR-001.
  - Schémas (revue architecture #6) : la correspondance module → schéma est une donnée, `packages/db/schemas.ts` (paquet `@rueda/db`).
    - Noms repris du SQL de 17 : AVL → `booking`, CAT → `catalog`, PAY → `payment`, FIN → `finance`, CFG → `config`. Schémas transverses : `platform` et `app`.
    - Les autres noms sont PROPOSÉS : `iam`, `kyc`, `pricing`, `contract`, `settlement`, `payout`, `trip_ops`, `claim`, `messaging`, `notification`, `review`, `support`, `risk`, `audit`, `reporting`, `outbox`. TRP prend `trip_ops`, et non `trip`, car la table `trip` appartient à AVL.
    - Bêta D1 : schéma unique `core` (PROPOSÉ), tables préfixées par leur schéma cible (`booking_checkout_hold`). Cette convention remplace le préfixe `avl_`, qui n'est plus valable.
    - US-005 (agent données) peut changer un nom PROPOSÉ tant qu'aucune migration ne l'utilise.
  - `Agent-Role` : CONTRIBUTING est aligné sur les noms de fichiers de `docs/team/roles/`.
  - `apps/web` : le texte « Panamá y Paraguay », codé en dur, est remplacé par l'emplacement de contenu `HOME_TAGLINE = '{home_tagline}'` (ADR-024 ; texte réel avec US-014 / US-121).
