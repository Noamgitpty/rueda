# Passation US-125 — Interrupteurs par pays et avertissements réglementaires (2026-11-12, agent back-end, claude-opus-5-5)

Branche `story/US-125-interrupteurs-pays`, partie de `origin/main`, worktree `../wt/US-125`, PR n° 122 en brouillon. **Statut : EN REVUE.** Décision : ADR-103 (PROPOSÉ).

- **Fait** (critères de 19 US-125) :
  1. **Fail-closed** : `core.config_go_live` rend `false` pour une clé absente, inconnue, de casse différente, un pays inconnu ou NULL (preuve L0, PA et PY).
  2. **RLS-27** : trigger `param_value_go_live_guard` (migration `0073_config_go_live_switch`) ; INSERT, UPDATE multi-lignes, DELETE d'une clé gardée refusés (42501) pour toute casse, avec ou sans contexte ; TRUNCATE refusé par 0008 ; app_api (ADMIN, SUPERADMIN) sans droit d'écriture. La garde de 0008 appelle la même règle en premier.
  3. **Deux personnes** : `core.config_cmd_request_go_live_switch` puis `core.config_cmd_approve_go_live_switch` (`cmd_golive_owner`, `EXECUTE` app_api seul) ; même personne (seconde session, acteur forgé) ⇒ `SELF_APPROVAL` journalisé ; deux personnes ⇒ nouvelle version, audit `GO_LIVE_SWITCH_APPLIED` avec la décision, événement `config.param.changed`.
  4. **Avertissements** : `regulatoryNotices` de `countries.json`, textes `common.regulatory.*` en es, en, fr et pt (catalogue v22), `GET /regulatory-notices`, écrans A10 et S03.
  5. **Hôte** : aucune route de l'hôte ne sert un interrupteur ; table des demandes illisible par tout rôle applicatif.
  - Suites : **S-04** (LEG_RELEASE passant, plafonné à la jambe HOST ; RT-CONC-24 : acteur seul, même personne deux fois, deux personnes ; RT-CONC-25 : approbations concurrentes), **N-20** (RLS-27 complet). N-41 non traité.
- **Défauts PROPOSÉS** (ADR-103) : référence `DEC-FONDATEUR-n`, expiration 72 h (constante), demandeur sans droit ⇒ `REJECTED`, une demande en attente par clé et pays, TOTP exigé ; textes des avertissements à valider par les avis.
- **Reste** :
  1. Revues : code, architecture, sécurité, argent, ux, qa ; RLS / `SECURITY DEFINER`, argent et concurrence sur un autre modèle.
  2. Écran de console des demandes (US-535) ; second approbateur humain (19 F-16) ; reports dans 17 (§2.3 : signatures `bytea` + identifiant de demande, préfixe `core.config_`, colonne `go_live_request_id`, expiration) et 16 A.8 (issues).
  3. Numéros : migration 0073, ADR-103, catalogue v22 (après US-126) ; à renuméroter si une PR passe avant.
- **Pièges** : S-04 ouvre `payouts_enabled` sur la base de **test** seulement, dans une fenêtre virtuelle lointaine (2500 à 2900) refermée à `false` par la même procédure (`test/support/golive.ts`, `openSwitchWindow`, fermeture dans un `finally` puis vérifiée, avant toute lecture) ; une transaction annulée ne suffit pas, car le versement est lu sous `app_worker` et les commandes ne s'exécutent que sous `app_api` (une valeur non validée est invisible d'une autre connexion) ; tout le reste se fait en transaction annulée. `migrator` et `COPY` ne sont pas éprouvés par test (règle relue en revue).
