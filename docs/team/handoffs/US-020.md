# Passation US-020 — Autres ports et adaptateurs `FAKE` (2026-11-03, agent integrations, claude-opus-5-5)

Branche `story/US-020-ports-fake`, worktree `.claude/worktrees/us-020-dev`, PR en brouillon. **Statut : EN REVUE**. Revues exigées : code, architecture, **sécurité** (C19, garde des FAKE, rappels signés), sur un autre modèle que l'auteur.

- **Fait** :
  - **Critère 1** (chaque port, FAKE couvrant réussite, échec, doublon et retard) : ports `IdentityProvider` (KYC), `EInvoicingProvider` (FIN), `MessagingChannel` (NTF), `SignatureService` (CTR), `MapTiles` (CAT) dans `apps/api/src/modules/<x>/internal/*.port.ts`, exportés en types par l'`index.ts` du module ; `FileStore` (revu) et `UploadScanner` (nouveau) dans `@rueda/db/audit`. FAKE dans `packages/fake-adapters` (`identity`, `e-invoicing`, `messaging`, `files`, `signature`, `maps`) sur un socle commun `src/core` (horloge virtuelle, scénario, idempotence, rappels signés). Pièces PA et PY, devises : lues dans `countries.json` par les tests (aucune constante pays). PAC synchrone et SIFEN asynchrone simulés.
  - **Critère 2** (image de production sans FAKE) : paquet privé et feuille, en `devDependencies` seulement ; `test/production-isolation.test.ts` balaie tout l'espace de travail ; garde centrale `assertFakeAllowed` (`RUEDA_ENV` explicite) dans chaque FAKE, testée sur sept environnements refusés.
  - **Report US-009** : `InMemoryFileStore` déplacé dans `@rueda/fake-adapters/files` ; `FakeKeyWrapper` reste dans `@rueda/db/testing` (cycle de paquets sinon, ADR-058 point 6) mais passe par la garde centrale (revue sécurité US-009, constat 11). Port `FileStore` à échecs en valeurs ; `receiveFile` et `verifyFileAsset` adaptés (`OBJECT_MISSING`, panne ⇒ `FileAssetError`). Suites de `packages/db` : `RUEDA_ENV=test` dans `vitest.unit.config.ts` et `vitest.shared.ts`.
  - Docs : ADR-058, README de `packages/fake-adapters`, section audit de `packages/db/README.md`.
- **Reste** :
  1. **Chevauchement US-019** (développée en parallèle dans le même paquet). Fichiers communs : `src/guard.ts`, `tsconfig.json`, `vitest.config.ts` de `packages/fake-adapters` et `apps/api/vitest.config.ts` sont **identiques octet pour octet** à ceux d'US-019 (fusion sans conflit) ; `packages/fake-adapters/package.json`, `src/index.ts`, `README.md`, `apps/api/package.json` (US-019 ajoute aussi `@rueda/money`) et `pnpm-lock.yaml` divergent : conflits triviaux, garder l'**union** (exports `./psp` + sous-chemins d'US-020 ; `export * from './psp/index.ts'` + exports d'US-020 ; deux sections du README). ADR : US-018 (PR #43) a pris ADR-057, d’où ADR-058 ici ; US-019 porte « ADR-056 », déjà pris dans `main`, et doit renuméroter.
  2. Fusionner les deux formats de rappel signé (`src/psp/signature.ts` d'US-019, `src/core/webhook.ts` d'US-020) quand les deux stories seront dans `main`.
  3. Reports (orchestrateur) : 17 §5 et §8.1 (ADR-058), ADR-051 (emplacement du FAKE `FileStore`, garde `RUEDA_ENV`).
  4. Hors périmètre : adaptateurs réels (lot C) ; câblage Nest des ports (stories KYC, NTF US-021, CTR, FIN, CAT) ; branchement d'`UploadScanner` sur la réception (story du téléversement) ; nettoyage des objets orphelins après `TIMEOUT` (US-003) ; `GeoProvider`, `ScreeningProvider`, `CalendarFeed`, `TelematicsProvider` (différés, 17 §10).
- **Prochaine commande exacte** : `pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test:unit && pnpm format:check`, puis `gh pr checks <n°>` (les suites L0 d'audit `l0-aud-02` / `l0-aud-03`, modifiées pour l'import du FAKE, ne tournent qu'en CI).
- **Pièges / hypothèses** :
  - Toute suite qui construit un FAKE doit poser `RUEDA_ENV=test` (configuration Vitest) ; sans elle, `FakeForbiddenError`.
  - `@rueda/fake-adapters` ne doit **jamais** importer un paquet de l'espace de travail (cycle refusé par Turborepo ; le test d'isolement le vérifie).
  - Types en double (port / FAKE) : volontaire, la conformance est vérifiée par `pnpm typecheck` via les `*.port.test.ts`.
  - `FileStore.put` en `DUPLICATE` rend `CONFLICT` alors que l'objet de l'appelant est en place : cas voulu (ADR-058, conséquences).
  - PostgreSQL local non démarré : la CI fait foi pour `test:l0`.
- **Paramètres créés (17 §7.2)** : aucun (borne OTP ≤ 10 min de 17 §2.7 passée en option du FAKE ; durées de session et fenêtres de rappel : options du test). **Entités / migrations** : aucune.
- **Tests ajoutés et état** : `@rueda/fake-adapters` 72 tests (garde, socle, sept FAKE, isolement) ; `@rueda/api` 5 tests de conformance ; `@rueda/db` tests de `receiveFile` / `verifyFileAsset` sur échecs du stockage. Local : `lint`, `typecheck`, `test:unit`, `format:check` verts. **Décisions** : ADR-058 PROPOSÉ.
