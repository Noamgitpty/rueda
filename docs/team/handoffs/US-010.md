# Passation US-010 — Comptes, sessions et port d'authentification (2026-11-03, agent back-end, claude-opus-5-5)

Branche `story/US-010-comptes-sessions`, worktree `.claude/worktrees/us-010-dev`, PR en brouillon. **Statut : EN REVUE**. Revues exigées : code, architecture (schéma IAM, ADR-052), **sécurité** (`SECURITY DEFINER`, sessions, cookies, secrets), sur un autre modèle que l'auteur.

- **Fait** :
  - Migrations `0010_iam_identity` (10 tables `core.iam_*` de 17 §3.2.1, RLS `ENABLE` + `FORCE`, aucun droit de table pour les rôles applicatifs, trigger `session_guarded_columns`) et `0011_iam_auth_commands` (7 commandes `SECURITY DEFINER`, `EXECUTE` au seul `app_api`). Fixtures de test `9200_test_iam_fixtures`.
  - Port d'authentification dans `apps/api/src/modules/iam` : `AuthenticationPort`, `SessionGuard`, `principalOf`, adaptateur interne `AuthService`, `PgAuthStore`, routes `/auth`. `main.ts` monte `ApiModule` (AppModule + IamAuthModule) avec les adaptateurs PostgreSQL ; le travailleur ne monte pas les routes.
  - Critère 1 (hachage robuste) : argon2id `node:crypto` (vecteur RFC 9106 §5.3) + `CHECK` de la base qui refuse toute valeur non argon2id.
  - Critère 2 (session révoquée ⇒ 401) : prouvé sur le FAKE (test:unit), sur PostgreSQL par HTTP de bout en bout (test:int, apps/api) et au niveau des commandes (test:l0, packages/db).
  - Sécurité des sessions : expiration à l'horloge de la base, révocation définitive, « déconnexion partout », fixation (jeton neuf + révocation du jeton présenté), cookie `__Host-session; HttpOnly; Secure; SameSite=Lax`, CSRF (JSON obligatoire), anti-énumération, limiteur, aucun secret dans les journaux (test de capture), refus de démarrer hors `app_api`, `trust proxy` configurable.
  - Clés i18n `common.auth.*` (10 clés) en es, en, fr ; `CATALOG_VERSION` = 2.
  - Corrections des revues du 2026-11-03 (architecture et code : CHANGEMENTS DEMANDÉS ; sécurité : APPROUVÉ) :
    - `IamAuthModule` global ; test `session-guard.test.ts` avec un module consommateur qui n'importe pas `register()` et un contrôleur gardé par `SessionGuard` seul (retirer le `throw` de la garde fait échouer 2 tests, vérifié par mutation) ;
    - contrôle CSRF (JSON exigé) déplacé dans `SessionGuard` pour toute écriture gardée, et dans `JsonWriteGuard` pour les routes `/auth` ;
    - `logout` / `logout-all` : révocation avant l'effacement du cookie ;
    - la vérification de l'email révoque les sessions antérieures (`EMAIL_VERIFIED`) ; le principal porte `emailVerified` ;
    - `trust proxy` par `RUEDA_API_TRUST_PROXY` (défaut : aucun mandataire ; valeur invalide : refus de démarrer) ;
    - test du coût égal (`auth.service.test.ts`) : une vérification argon2id aux mêmes paramètres dans tous les cas d'échec ;
    - fusion d'`origin/main` (US-013 : 0008, 0009) et migrations renumérotées `0010` et `0011` (règle d'US-008 : numéro strictement supérieur au maximum de main ; plus de plage 0200). `9200` est conservé (unique).
  - Documentation : ADR-052, README du module IAM (une ligne) et `apps/api/src/modules/iam/AUTH.md`, section « Schéma IAM » de `packages/db/README.md`, `docs/ops/ENV_VARS.md` (variables `PG*` et `RUEDA_API_TRUST_PROXY` de l'API).

- **Pièges / hypothèses** :
  - Commandes `SECURITY DEFINER` sous `migrator` (même raison qu'ADR-048) ; la limite RLS-18 s'applique : du SQL arbitraire sous `app_api` peut ouvrir une session pour un compte.
  - `apps/api` a désormais un `test:int` : deuxième banc PostgreSQL en parallèle sous Turborepo (un conteneur par paquet en CI ; en local P-07, le verrou d'instance les sérialise).
  - `apps/api/tsconfig.json` permet `allowImportingTsExtensions` (pour `@rueda/db/testing` dans les `*.int.test.ts`) ; la compilation de production le retire et exclut `testing/`.
  - Exports ajoutés à `@rueda/db` : `./testing/global-setup`, `./testing/setup-l0-05`.
  - `avl-schema.test.ts` ignore désormais les objets `iam_*` (couverts par `iam-schema.test.ts`).
  - Connexion autorisée en `PENDING_EMAIL` et `RESTRICTED` (ACC-001 « reprise à la connexion », la restriction limite la réservation) ; refusée en `CLOSED` et `BANNED` (PROPOSÉ).
  - PostgreSQL local non démarré : la CI fait foi.
