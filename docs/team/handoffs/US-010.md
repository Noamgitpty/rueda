# Passation US-010 — Comptes, sessions et port d'authentification (2026-11-03, agent back-end, claude-opus-5-5)

Branche `story/US-010-comptes-sessions`, worktree `.claude/worktrees/us-010-dev`, PR en brouillon. **Statut : EN REVUE**. Revues exigées : code, architecture (schéma IAM, ADR-052), **sécurité** (`SECURITY DEFINER`, sessions, cookies, secrets), sur un autre modèle que l'auteur.

- **Fait** :
  - Migrations `0200_iam_identity` (10 tables `core.iam_*` de 17 §3.2.1, RLS `ENABLE` + `FORCE`, aucun droit de table pour les rôles applicatifs, trigger `session_guarded_columns`) et `0201_iam_auth_commands` (7 commandes `SECURITY DEFINER`, `EXECUTE` au seul `app_api`). Fixtures de test `9200_test_iam_fixtures`.
  - Port d'authentification dans `apps/api/src/modules/iam` : `AuthenticationPort`, `SessionGuard`, `principalOf`, adaptateur interne `AuthService`, `PgAuthStore`, routes `/auth`. `main.ts` monte `ApiModule` (AppModule + IamAuthModule) avec les adaptateurs PostgreSQL ; le travailleur ne monte pas les routes.
  - Critère 1 (hachage robuste) : argon2id `node:crypto` (vecteur RFC 9106 §5.3) + `CHECK` de la base qui refuse toute valeur non argon2id.
  - Critère 2 (session révoquée ⇒ 401) : prouvé sur le FAKE (test:unit), sur PostgreSQL par HTTP de bout en bout (test:int, apps/api) et au niveau des commandes (test:l0, packages/db).
  - Sécurité des sessions : expiration à l'horloge de la base, révocation définitive, « déconnexion partout », fixation (jeton neuf + révocation du jeton présenté), cookie `__Host-session; HttpOnly; Secure; SameSite=Lax`, CSRF (JSON obligatoire), anti-énumération, limiteur, aucun secret dans les journaux (test de capture), refus de démarrer hors `app_api`.
  - Clés i18n `common.auth.*` (10 clés) en es, en, fr ; `CATALOG_VERSION` = 2.
  - Documentation : ADR-052, README du module IAM (une ligne) et `apps/api/src/modules/iam/AUTH.md`, section « Schéma IAM » de `packages/db/README.md`, `docs/ops/ENV_VARS.md` (variables `PG*` de l'API).
- **Reste** :
  1. **Règles de revue** : `docs/team/review-requirements.json` ne liste pas US-010 parmi les propriétaires de `packages/i18n/` ; la consigne impose de passer par `packages/i18n`. L'orchestrateur doit ajouter US-010 (ou déplacer les clés) : le job `revues` le signalera.
  2. Reports de spécification (orchestrateur) : ADR-052 dans 17 §8.1 et défaut d'ADR-021 ; écarts de 17 §3.2.1 (`email` en `text` minuscule, `PENDING_EMAIL`, `token_hash`, `revoked_reason`, `country_scope`) ; codes PROPOSÉS dans 16 A.8 : `AUTH_REQUIRED`, `AUTH_INVALID_CREDENTIALS`, `REQUEST_INVALID`, `SIGNUP_ACCEPTED`, `EMAIL_VERIFIED` ; paramètres de session au registre 17 §7.2 ; famille `iam_auth` dans la liste blanche RLS-15 (US-011).
  3. Hors périmètre : politiques RLS par acteur et par pays (US-011) ; TOTP staff et montée de `mfa_level` (US-012) ; envoi réel des emails (NTF) ; renvoi du lien de vérification ; SSO ; OTP ; vérification des mots de passe compromis (exige un fournisseur) ; réhachage à la connexion si les paramètres changent ; limiteur partagé entre instances ; consentement versionné CGU (LEG-002) ; FK des colonnes `guest_user_id` / `org_id` d'AVL vers IAM (les fixtures L0 d'US-006 devront créer des comptes) ; propriétaire dédié `iam_auth_owner` (amorçage).
- **Prochaine commande exacte** : `pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test:unit && pnpm lint:sql`, puis `gh pr checks <PR>` (le job « base de données » fait foi, ADR-043).
- **Pièges / hypothèses** :
  - Commandes `SECURITY DEFINER` sous `migrator` (même raison qu'ADR-048) ; la limite RLS-18 s'applique : du SQL arbitraire sous `app_api` peut ouvrir une session pour un compte.
  - `apps/api` a désormais un `test:int` : deuxième banc PostgreSQL en parallèle sous Turborepo (un conteneur par paquet en CI ; en local P-07, le verrou d'instance les sérialise).
  - `apps/api/tsconfig.json` permet `allowImportingTsExtensions` (pour `@rueda/db/testing` dans les `*.int.test.ts`) ; la compilation de production le retire et exclut `testing/`.
  - Exports ajoutés à `@rueda/db` : `./testing/global-setup`, `./testing/setup-l0-05`.
  - `avl-schema.test.ts` ignore désormais les objets `iam_*` (couverts par `iam-schema.test.ts`).
  - Connexion autorisée en `PENDING_EMAIL` et `RESTRICTED` (ACC-001 « reprise à la connexion », la restriction limite la réservation) ; refusée en `CLOSED` et `BANNED` (PROPOSÉ).
  - PostgreSQL local non démarré : la CI fait foi.
- **Paramètres créés (17 §7.2)** : aucun en base ; valeurs PROPOSÉES dans `internal/policy.ts` (session 14 j, lien 24 h, mot de passe ≥ 10, limites de débit) et bornes dures dans 0201 (300 s à 30 j, 8 h staff, lien 300 s à 7 j). **Entités / migrations** : `core.iam_user_account`, `iam_email_verification`, `iam_auth_factor`, `iam_session`, `iam_otp_challenge`, `iam_organization`, `iam_membership`, `iam_staff_role_assignment`, `iam_role_permission`, `iam_restriction` ; migrations 0200, 0201 ; test 9200.
- **Tests ajoutés et état** : test:unit `@rueda/api` 66 verts en local (argon2id, primitives, contrat FAKE, HTTP FAKE, catalogue i18n, isolement des FAKE) ; test:int `@rueda/api` (contrat et HTTP sur PostgreSQL) et `@rueda/db` (`iam-schema`), test:l0 `@rueda/db` (`iam-sessions`, 9 tests) : **CI seulement**. **Décisions** : ADR-052 PROPOSÉ.
