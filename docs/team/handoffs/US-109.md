# Passation US-109 — Fiche 360° et files de revue (2026-11-11, agent full-stack, claude-opus-5-5)

Branche `story/US-109-fiche-360-files-revue`, worktree `../wt/US-109`, PR #110 (brouillon). **Statut : EN REVUE**. Revues exigées : code, architecture, **sécurité** (RLS, `SECURITY DEFINER`, C2 / C3, fichiers ; autre modèle), ux, qa. Décision : ADR-097 (PROPOSÉ).

- **Fait** :
  - **Critère 1** (`ACCOUNT_RESTRICTED`) :
    - actions `RESTRICT_ACCOUNT` et `LIFT_RESTRICTION` (cadre d'ADR-092, sujet `USER_ACCOUNT`, `ops.restrict_account`, saisie `kind` ∈ {`TS_HOLD`, `POLICY_VIOLATION`}, motif obligatoire) ;
    - gestionnaire `core.iam_manual_action_restriction` (`iam_auth_owner`) ;
    - `booking_cmd_place_hold` refuse un voyageur restreint et le véhicule d'un titulaire restreint (`HOST_NOT_ACTIVATED`, L1-PM-33).
  - **Critère 2** (journal d'accès KYC) : dossier KYC par la file KYC seulement (élément assigné ; ADMIN : sa portée ; `kyc.read_sensitive`). `READ_C3` est écrit au journal AVANT la lecture. Fiche 360° : `READ_C2_SUPPORT`, couverture par dossier ou élément assigné (17 §2.3).
  - **Critère 3** (retard signalé) : échéance posée par la base à la mise en file (`kyc_review_sla_business_h`, `listing_review_sla_h`, `catalog_addition_sla_business_h`, `review_hold_minutes`) ; `overdue` calculé à la lecture, en tête de file et compté au résumé.
  - Reports d'US-101 :
    - notes internes (ajout seul) ;
    - ouverture et changement d'état des `support_case` ;
    - pièces du staff : taille, type réel (liste blanche JPEG, PNG, HEIC, PDF), droit jugé avant l'analyse, antivirus fail-closed, ligne `file_asset` `PRIVATE_EVIDENCE` C2 puis dépôt chiffré dans une transaction. En production, les adaptateurs sont indisponibles (503).
  - API SUP : `GET /console/queues` et 8 routes `POST` (README SUP, OpenAPI, matrice des routes, contrats). Back-office : écran O01 (`ops-view.tsx`), en es, en, fr et pt-BR (catalogue v15).
  - Docs : ADR-097, README SUP, `@rueda/db` et back-office, `COMME_TURO.md` (2 lignes), Q-019, CHANGELOG, matrices (autorisations, données personnelles, RLS-15).
- **Seconde passe** (revues du 2026-11-12, sécurité, architecture et UX en changements demandés) :
  - restrictions : jamais sur soi-même (`SELF_FORBIDDEN`) ; un membre du staff seulement par un ADMIN (`STAFF_SUBJECT_ADMIN_ONLY`, PROPOSÉ, ADR-097) ; tests PA et PY ;
  - `support_enqueue_review` en SECURITY DEFINER (`iam_staff_owner`, `EXECUTE` à personne), pays recoupé (`COUNTRY_MISMATCH`), clôture `support_close_review_item` ; preuve L0 par une sonde productrice (`cmd_golive_owner`, `EXECUTE` seul) ;

- **Pièges / hypothèses** :
  - Le littéral `'now'` est refusé par le lint d'horloge SQL, même comme clé jsonb.
  - `findForeignStrings` : un nom d'emplacement (`{overdue}`) compte comme du texte ; un mot espagnol contenu dans un texte portugais (« verificado », « Tipo », « Desde ») est refusé.
  - Les écritures de l'API sont en JSON seulement (parade CSRF) : les pièces passent en base64, 64 Kio au plus en Bêta.
  - Pays d'une personne = `ctr_account_country`. Une personne sans pays déclaré n'est visible de personne (FORBIDDEN).
  - PostgreSQL local non démarré : migration, L0 et `test:int` prouvés par la CI seulement.
