# Passation US-107 — Compte d'hôte : organisation d'une personne physique, titulaire et nom affiché (2026-11-11, agent back-end, claude-opus-5-5)

Branche `story/US-107-compte-hote`, worktree `../wt/US-107`, PR en brouillon. **Statut : EN REVUE**. Revues exigées (`review-requirements.json`) : code, architecture, **sécurité** (RLS, `SECURITY DEFINER`, liaison au cadre d'ADR-092 ; autre modèle que l'auteur), qa. Décision : ADR-096 (PROPOSÉ).

- **Fait** :
  - **Critère 1** (une personne, un compte d'hôte) : une seconde demande dans le même pays rend `HOST_ACCOUNT_EXISTS` (409), quel que soit le statut du premier compte. Deux demandes concurrentes sont sérialisées (verrou consultatif personne + pays). Un compte par pays : 17 §2.3.
  - **Critère 2** (personne morale) : `HOST_ENTITY_NOT_ALLOWED` (422) pour `holderKind` ≠ `INDIVIDUAL`, ou pour une donnée d'entreprise dans le corps (`legalName`, `tradeName`, `companyName`, `businessName`, `companyTaxId`, `legalEntity`). Défense en profondeur : la commande, la politique d'insertion d'`iam_auth_owner` et la contrainte `organization_kind_valid` de 0010.
  - **Critère 3** (compte non `ACTIVE`) : le compte s'ouvre `ONBOARDING` ; la pose réelle d'un hold sur son véhicule est refusée (`HOST_NOT_ACTIVATED`, prouvé en PA et PY). **Partiel** : la soumission d'un véhicule n'existe pas encore (US-115 / US-124 reprennent le contrôle).
  - **Critère 4** (reconnexion) : `GET /auth/session` rend `roles: ["GUEST", "P2P_HOST"]` et `hostAccounts` ; nom affiché = prénom légal, jamais une raison sociale ni le nom de famille.
  - Action de console **`CREATE_HOST_ACCOUNT`** branchée par le cadre `manual_action` :
    - type de sujet `USER_ACCOUNT` déclaré, avec le résolveur `support_country_of_user_account` (pays du compte de la personne) ;
    - gestionnaire `iam_manual_action_create_host_account` (`SECURITY DEFINER`, `iam_auth_owner`, EXECUTE au seul `iam_staff_owner`), conforme à la garde de liaison ;
    - bouton du back-office en es, en, fr et pt-BR.
  - **L1-PM-11** : IDOR hôte A contre hôte B en PA et en PY :
    - lecture : chacun ne lit que ses lignes ;
    - `org_id` forgé : 0 ligne ;
    - écriture directe : 42501 ;
    - comptes de la session : jamais ceux de l'autre ;
    - commande de domaine et gestionnaire : non exécutables par `app_api`, `app_worker` ni `app_anon` ;
    - même personne dans deux pays : chaque contexte ne voit que son pays.
  - Textes `common.host.*` et `backoffice.action.CREATE_HOST_ACCOUNT` en es, en, fr, pt-BR (catalogue v13).
  - OpenAPI : `POST /host/accounts`, `Session.roles`, `Session.hostAccounts` ; suite de contrat `/host`. Matrice des routes et `api.md`, `modules.md` régénérés. Documentation : ADR-096, README de `@rueda/db` et d'IAM, `AUTH.md`, `COMME_TURO.md` (deux lignes), fragment de CHANGELOG.
