# Passation US-123 — Inscription et KYC individuel de l'hôte, profil fiscal (2026-11-12, agent back-end, claude-opus-5-5)

Branche `story/US-123-kyc-hote`, worktree `../wt/US-123`, PR #124 en brouillon. **Statut : EN REVUE.** Revues exigées (`review-requirements.json`) : code, architecture, **sécurité**, **argent**, ux, qa ; sécurité et argent sur un autre modèle que l'auteur. Décision : ADR-105 (PROPOSÉ).

- **Fait** (critères de 19 US-123, prouvés en L0 PA USD et PY PYG sous `app_api`) :
  - **1** : 20 ans (date lue par le KYC), `host_min_age_years` = 21 ⇒ `HOST_UNDER_AGE`, aucun dossier ; 21 ans et un jour ⇒ soumis. Date inconnue ⇒ `HOST_AGE_UNVERIFIED`.
  - **2** : personne morale ⇒ `HOST_ENTITY_NOT_ALLOWED` (compte d'hôte, profil fiscal en base et en API : `taxpayerKind`, champs d'entreprise).
  - **3** : sans numéro fiscal (RUC seul admis au Paraguay, types tirés de `config_country.host_tax_id_kinds`) ⇒ `DOCS_PENDING`, décision refusée, compte non activable ; numéro chiffré par la clé du sujet `ORG` avant l'écriture (C2, crypto-shredding), jamais en clair ni dans l'audit.
  - **4** : KYC approuvé, sous-marchand absent ou `PENDING` ⇒ tentative d'activation refusée (`HOST_PAYOUT_RAIL_UNAVAILABLE`) ; sous-marchand `ACTIVE` ⇒ ce blocage disparaît.
  - **5** : correspondance ⇒ `BLOCKED`, motif `HOST_SANCTIONS_HIT` journalisé (code seulement) ; versions des listes et référence opaque seulement dans `kyc_sanctions_screening`, jamais dans l'audit, les événements ni l'API.
  - **6** : interrupteurs à `false` ⇒ dossier `APPROVED`, compte `PENDING_ACTIVATION`, blocages `P2P_HOSTS_DISABLED` et `INSURER_CONTRACT_INACTIVE` ; garde en base (politique `kyc_cmd_host_update`) ; explication `web.a07.waitingCountry` en es, en, fr, pt (e2e). **Aucun interrupteur écrit**, nulle part.
  - Suites : **N-38** (âge revérifié à l'activation, `iam.organization.created` une fois à la première activation) ; **N-28** partiel (résidence vérifiée du KYC prioritaire, refus si elle diverge du pays du compte d'hôte ; `ctr_account_country` et `iam_user_account.residence_country` inchangés) ; **N-66** (CGU de l'hôte exigées au dossier et à l'activation) ; **N-37** déjà couverte par US-115 (0067).
  - API `/host/accounts/{orgId}/verification` (+ `/tax-profile`), ports `SanctionsScreener` et `TaxIdSealer`, FAKE du filtrage ; console `HOST_VERIFICATION_DECISION` liée ; file `HOST_VERIFICATION` ; écran A07 `/host/verification` ; catalogue v24.
- **Reste / proposé** :
  1. **Découpage proposé** : enregistrement du sous-marchand (`registerSubmerchant` sur le FAKE) par un consommateur `payment_command` de `kyc.host_verification.decided`, puis nouvelle tentative d'activation : **non fait ici** (story à créer, argent).
  2. Chemin `ACTIVE` non prouvé de bout en bout (interrupteurs) : en préproduction par la commande à deux personnes d'US-125.
  3. Reports d'ADR-105 : format du numéro fiscal par pays (paramètre CFG), libellés des types de numéro, filtrage continu (VER-009), revue partielle après approbation, revérification automatique de l'activation, N-28 côté CTR.
  4. Renuméroter si `main` avance (0075, ADR-105, v24, 9986 réservés) et recopier `schema.md`.

- **Pièges** :
  - US-125 (0073) et US-114 (0074) fusionnées dans la branche : numérotation contiguë.
  - `schema.md` imprimé par la CI est entrelacé avec la sortie de vitest et de turbo : retirer horodatages, lignes `ERROR`, `##[error]`, `❯ …`, `× …`, recoller la ligne coupée, aucune ligne vide finale.
  - Écrire le SQL en `\n` : un script Python en mode texte sous Windows écrit `\r\n`.
  - `platform.now()` vaut `clock_timestamp()` : jamais comparer deux appels ; deux événements de la même milliseconde n'ont pas d'ordre (`uuid_v7`).
  - Liste blanche RLS-15 : les signatures sont triées en JS et en SQL (collation) ; un nom qui en prolonge un autre (`kyc_cmd_apply_decision` / `…_facts`) les fait diverger : d'où `kyc_cmd_decide_with_facts`.
