# Passation US-026 — Évaluation PWA sur iOS (2026-10-31, agent front-end, claude-opus-5-5)

- **Fait** :
  - Interfaces d'appareil isolées dans `apps/web/device/` (point d'entrée `index.ts`), conformes à ADR-005 et 17 §6.2 :
    - `CameraCapture` : `getUserMedia` + canevas, jamais d'entrée fichier ; ≤ 1 600 px et ≤ 500 ko par paliers de qualité ; SHA-256 sur l'appareil ;
    - `OfflineQueue` : stockage injecté, IndexedDB pour le web ; AES-GCM avec clé non exportable ; ordre par `seq` ; vérification d'empreinte à la lecture ; vidage ordonné qui s'arrête au premier échec ;
    - `DeviceGeo` : issues typées, sans exception.
  - Laboratoire jetable `/lab/pwa-ios` : page, manifeste, service worker de portée `/lab/pwa-ios` et icônes PNG provisoires. Dix tests produisent un JSON copiable et un rapport complet.
  - Le laboratoire est coupé par `WEB_LAB_PWA_IOS_ENABLED` (exactement `true`), désactivé par défaut et lu à chaque requête. Sans lui, tout répond 404. Le drapeau est documenté dans `apps/web/README.md` et `apps/web/.env.example`.
  - Protocole pour le fondateur : `docs/qa/US-026-protocole-pwa-ios.md`. Il couvre les appareils, l'ouverture de la page (Wi-Fi local, préproduction), les étapes, les critères C1 à C9, le gabarit de résultat et la règle de décision ADR-005.
  - `vitest` ajouté à `apps/web` (script `test:unit`).
- **Reste** (hors de portée d'un agent) :
  - Campagne sur de vrais iPhone et Android avec le fondateur et les agences, en HTTPS, donc après US-003 (préproduction) ;
  - test de purge à J+8 ;
  - grille remplie, inscription au registre P-04 en cas d'échec iOS, décision ADR-005 du fondateur en fin de lot 0.
- **Prochaine commande exacte** : en préproduction (US-003), définir `WEB_LAB_PWA_IOS_ENABLED=true` pour la durée de la campagne seulement, puis envoyer au fondateur `https://<préprod>/lab/pwa-ios`. En local : `pnpm --filter @rueda/web build`, puis `$env:WEB_LAB_PWA_IOS_ENABLED='true'; pnpm --filter @rueda/web start`.
- **Pièges / hypothèses** :
  - Sans HTTPS (IP locale en `http://`), iOS bloque `getUserMedia`, le service worker, la géolocalisation et `crypto.subtle`. La page l'affiche.
  - Next répond avec `Vary: rsc, …` : le service worker range par URL et relit avec `ignoreVary`.
  - Le pré-cache de l'installation est « au mieux » : s'il échouait, le navigateur supprimerait l'enregistrement.
  - La portée `/lab/pwa-ios` (sans barre finale) exige l'en-tête `Service-Worker-Allowed`.
  - Le panneau navigateur intégré de Claude refuse tout service worker. Le profil Chrome placé dans le bac à sable échoue sur `Cache.put` (« Entry already exists »). Pour vérifier, utiliser un contexte CDP éphémère (`Target.createBrowserContext`).
  - Sur iPhone, Safari et l'application installée ont des stockages séparés.
  - La version d'iOS lue dans l'agent utilisateur peut être figée : le protocole demande celle des Réglages.
  - Les textes du laboratoire sont en français, regroupés dans `lab-text.ts` : c'est le prototype jetable, seule exception de la story. Le CSS n'utilise que des variables locales et des couleurs système, en attendant les jetons d'US-030.
- **Paramètres créés (17 §7.2)** :
  - aucun. `DEFAULT_PHOTO_POLICY` (1 600 px, 500 000 octets, paliers de qualité) et le seuil « photo fraîche » de 120 s sont PROPOSÉ ; ce sont des candidats à des paramètres CFG quand US-302 / US-303 les utiliseront.
  - Seuil de précision C5 (≤ 100 m) : PROPOSÉ dans le protocole.
  - Entités / migrations : aucune.
- **Tests ajoutés et état** :
  - 53 tests unitaires dans `apps/web` : `device/*.test.ts` et `app/lab/pwa-ios/lab.test.ts`. Les empreintes attendues viennent de `node:crypto`, pas du code testé. Tous verts.
  - Vérifié à la main avec `next start` :
    - drapeau coupé : 404 sur les 4 routes ;
    - drapeau actif : 200, bons types de contenu, en-tête `Service-Worker-Allowed` ;
    - sous Chrome sans interface : service worker actif et page contrôlée, événement `sync` reçu, page rouverte serveur arrêté, file chiffrée vérifiée puis vidée, témoins écrits et relus aux trois endroits.
  - **Non vérifié** : tout ce qui est propre à iOS et Safari (protocole §7).
- **Décisions prises (ADR / DECISIONS)** :
  - aucune décision d'architecture nouvelle : les interfaces sont celles de 17 §6.2 ;
  - la décision ADR-005 (PWA seule, enveloppe native ou terminal fourni) reste au fondateur, en fin de lot 0, selon la règle du protocole §8.
