# Passation US-101 — Cadre des actions de console (`manual_action`) (2026-11-11, agent back-end, claude-opus-5-5)

Branche `story/US-101-cadre-actions-console`, worktree `../wt/US-101`, PR #99 (brouillon). **Statut : EN REVUE**. Revues exigées : code, **sécurité** (RLS, rôles, `SECURITY DEFINER`, SQL dynamique) et architecture (`packages/db/`), sur un autre modèle que l'auteur. Décision : ADR-091 (PROPOSÉ).

- **Fait** :
  - **Critère 1** (action d'état ⇒ commande de domaine dans la même transaction, aucun montant saisi) :
    - catalogue minimal de 17 §10 : 10 actions d'état, 6 d'enregistrement seul, 3 FINANCE ;
    - table de liaison `support_manual_action_handler`, écrite par migration seulement ; signature et droits vérifiés par déclencheur ;
    - appel de la commande liée dans la commande de console (`EXECUTE` sur le nom lu dans `pg_proc`, valeurs liées), puis ligne et audit ; une erreur annule tout ;
    - `input` : clés déclarées seulement, chaînes, jamais un nombre ni une chaîne numérique ; contrainte de catalogue contre les clés qui nomment un montant ;
    - actions d'état sans commande livrée : `UNAVAILABLE`, journalisé.
  - **Critère 2** (enregistrement seul ⇒ motif et pièces, journalisé) : au moins une pièce `audit_file_asset` du seau `PRIVATE_EVIDENCE` (20 au plus) ; ligne rattachée à son audit.
  - **Critère 3** (FINANCE ⇒ demande, puis seconde personne) : les trois actions sont liées à `cmd_request_finance_action` (0036). L'approbation passe par `cmd_approve_finance_action` ; le demandeur est refusé (`SELF_APPROVAL`, RLS-24).
  - API SUP :
    - contexte STAFF posé dans l'instruction ;
    - `GET /console/finance/approvals` et `POST /console/finance/approvals/{id}/approve` ;
    - codes PROPOSÉS `STAFF_ACTION_REQUESTED`, `STAFF_ACTION_REFUSED`, `STAFF_SELF_APPROVAL` ;
    - OpenAPI, matrice des routes, contrats, `docs/architecture/api.md` et `modules.md` régénérés.
  - Back-office : actions groupées, champ des pièces, note « aucun montant », demandes FINANCE à approuver (FINANCE et ADMIN) ; es, en, fr, pt-BR, catalogue v11.
  - Docs : ADR-091 ; `packages/db/README.md` (section « Cadre des actions de console ») ; README SUP et back-office ; `AUTH.md` ; `COMME_TURO.md` (pièces obligatoires) ; `docs/architecture/schema.md` régénéré par la CI.

- **Pièges / hypothèses** :
  - Un `oidvector` (`pg_proc.proargtypes`) est indexé à partir de 0 : il n'est jamais égal à un `ARRAY[]`. La garde de liaison compare donc des textes.
  - La ligne de la dérogation `dynamic-sql` (`expand-contract-allowlist.json`, ligne 458 de 0059) suit le fichier. Toute édition au-dessus de l'`EXECUTE` impose de la recaler (`node packages/db/src/expand-contract/cli.ts` donne la ligne).
  - Numérotation : 0059 (migration), 9960 (fixture), ADR-091. Si `main` avance, renuméroter : fichiers, en-têtes, allowlist, README, ADR-091, `schema.md`, cette passation.
  - La forme d'US-012 (6 arguments) délègue au cadre : une action d'enregistrement seul y est refusée (`22023`, pièce obligatoire) ; `l0-staff-console` passe à la forme à pièces.
  - Une commande FINANCE liée exige le contexte STAFF (`app.actor_kind`, portée) : sans lui, la demande rend `AUTH_REQUIRED`, donc `REFUSED`.
  - `findForeignStrings` : un texte de test qui contient un mot d'un autre catalogue (« Motivo ») fait échouer la vue ; les échantillons utilisent des valeurs neutres.
  - PostgreSQL local non démarré : la CI fait foi.
