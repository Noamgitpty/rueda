Branche `story/US-006-preuves-l0-exclusion`, worktree `.claude/worktrees/us-006-dev`, PR #31 (brouillon). **Statut : EN REVUE**. Revues exigées par la CI : code, architecture (ADR-047, migrations), **sécurité** (RLS, `SECURITY DEFINER`, concurrence) et QA, sur un autre modèle que l'auteur.

  - Critère L0-01 :
    - avec concurrent : `23P01` sur l'`UPDATE` lui-même, `ROLLBACK TO SAVEPOINT`, transaction toujours utilisable ;
    - bloc C validé : hold `COMPENSATED`, disposition `COMPENSATION`, `SLOT_LOST_AFTER_EXPIRY`, code `VEHICLE_UNAVAILABLE`, une seule occupation active ;
    - sans concurrent : trip `BOOKED`, occupation `TRIP` active ;
    - rejeu idempotent.
  - Critère L0-03 :
    - désactivation de l'occupation, changement de `ref_id`, trip sans occupation, occupation `TRIP` orpheline : refus **au COMMIT** (`23000`, `INVARIANT_VIOLATION`) ;
    - suppression : `42501` pour les rôles applicatifs, `23503` (FK du hold) même forcée par le propriétaire ;
    - état terminal ou raccourcissement dans la même transaction : accepté ;
    - bloc C sur un hold `COMPENSATED` : 0 ligne, aucune erreur ;
    - toute sortie de `CONVERTED` ou de `COMPENSATED` est refusée (`INVALID_TRANSITION`) ;
    - `CONVERTED` sans disposition : refusé ; disposition sur un remboursement : refusée ;
    - coût mesuré (50 conversions, valeur dans le journal CI `[L0-03]`).
  - Critère L0-08 : chaque doublon donne `23505` puis un code métier, sans message ni `DETAIL` :
    - `webhook_inbox` à `psp_account_id` nul → `WEBHOOK_DUPLICATE` ;
    - deux holds vivants du même guest sur le même véhicule → `HOLD_ALREADY_LIVE`, et un nouveau hold est accepté après l'expiration ;
    - deux dispositions `CONVERSION` → `DUPLICATE_PAYMENT` ;
    - conversion puis compensation de la même opération → `DISPOSITION_EXISTS`.
  - Tous les tests L0 tournent en USD (PA) et en PYG (PY). Documentation : `packages/db/README.md` (section « Schéma AVL / PAY ») et ADR-047.

- **Pièges / hypothèses** :
  - **`cmd_hold_owner` est inutilisable tel quel.** `migrator` ne peut pas lui céder une fonction (`ALTER FUNCTION … OWNER TO` exige d'en être membre), et l'amorçage refuse toute appartenance. US-023 doit trancher.
  - Les fonctions de trigger d'intégrité sont donc `SECURITY DEFINER` sous `migrator` (ADR-047), parce qu'un trigger différé tourne au COMMIT sous le rôle de la session (PostgreSQL 16).
  - Les états qui tiennent le créneau (`BOOKED` à `UNRETURNED`, `START_WINDOW_EXPIRED` compris) sont une lecture de SM-1, PROPOSÉE.
  - Le contrôle I-OCC ne verrouille pas le trip. Le raisonnement est dans ADR-047 point 5 : au pire un refus en trop, jamais une acceptation à tort.
  - Sous RLS, PostgreSQL omet déjà les valeurs de clé du `DETAIL` des `23505` et `23P01`.
  - FK en attente : `vehicle_id`, `guest_user_id`, `org_id`, `quote_id`, `listing_id`, `psp_account_id` et `refund_instance_id` sont des `uuid` sans clé étrangère.
  - Les travailleurs n'ont pas `INSERT` sur occupations, holds ni opérations : seules les commandes et les fixtures en créent.
  - La règle de revue du paquet `packages/db` (architecture) s'applique. Si la CI signale `packages/db` « réservé à US-001, US-005 », c'est attendu : une autre PR met à jour ces règles.
