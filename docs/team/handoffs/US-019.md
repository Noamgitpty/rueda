# Passation US-019 — Port `PaymentProvider`, adaptateur `FAKE` et idempotence (2026-11-03, agent integrations, claude-opus-5-5)

Branche `story/US-019-port-paiement-fake`, worktree `.claude/worktrees/us-019-dev`. PR brouillon. Revues exigées : code, architecture, **sécurité** et **argent** (autre modèle), qa.

- **Fait** :
  - **Critère 1** (même clé, montant différent ⇒ `IDEMPOTENCY_CONFLICT`) : commande `core.payment_cmd_record_operation` (montant, devise, nature, objet, compte, tentative, `idem_sent` **et jambes** comparés) ; FAKE (conflit chez le PSP) ; suite de contrat. Preuves : `l0-pay-port.test.ts` (USD, PYG), `testing/contract.ts`.
  - **Critère 2** (signature invalide ou doublon) : `WebhookIngestService` + `core.payment_cmd_receive_webhook` : `REJECTED_SIGNATURE` (401, journalisé, aucun événement), doublon ⇒ 200 sans traitement (`webhook_inbox_dedup`), quarantaine à ± 5 min (heure de la base).
  - **Critère 3** (C19) : trigger `psp_account_fake_guard` + `CHECK` SANDBOX ; `assertPaymentStartup` (main.ts) ; registre de production vide ⇒ `/webhooks/FAKE/…` 404 sans requête ; base en production ⇒ `NOT_FOUND` sans écriture ; `@rueda/fake-adapters` en dépendance de développement, garde `RUEDA_ENV`.
  - **Critère 4** (FAKE hostile scriptable) : `packages/fake-adapters` (`FakePsp`) : doublons, désordre, retards, pertes, rejeu, ordres Yappy de 300 s, réponses inconnues / illisibles, panne, refus « ne pas réessayer », idempotence ignorée, capacités absentes ou `DOCUMENTED`.
  - **Critère 5** (`LegAmounts` sur toute méthode qui déplace des fonds) : `port.ts`, vérifié par les types (`port.test.ts`) ; contrôle avant appel (adaptateur), dans la commande SQL et au COMMIT.
  - **Critère 6** (aucun PAN ni CVV) : schéma inspecté (deux bases), contrainte `webhook_inbox_no_pan`, masquage avant stockage.
  - Idempotence d'envoi (17 §4.3) : `MoneyCommandSender`, vecteurs **T51, T52, T68** (attendus des oracles). Traitement asynchrone : `WebhookProcessor` (lire puis appliquer, rangs, quarantaine 15 min).
  - Migration `0027_payment_psp_port`, test `9400_test_payment_fixtures` ; liste blanche RLS-15 (+6) ; ADR-056 ; README de PAY (`apps/api/src/modules/pay/internal/README.md`), de `packages/db` et de `packages/fake-adapters`.

  1. Reports dans 17 et 16 A.8 listés par ADR-056 (orchestrateur).
  2. US-003 : migration d'environnement (`platform.deployment_env()`), coffre des secrets de webhook, chiffrement du corps brut (`raw_body_enc`), câblage du travailleur (`assertPaymentStartup`, `WebhookProcessor`, `MoneyCommandSender`), limite du corps JSON d'Express (100 ko par défaut, < 256 ko).

  4. US-061 : port de place de marché, capacités bloquantes à l'activation de l'hôte, mode « prorata » (TJ10c).
  5. Report US-009 : déplacer `FakeKeyWrapper` / `InMemoryFileStore` dans `packages/fake-adapters` (non fait ici).
  6. US-125 : rouvrir `PLATFORM_MOR` derrière `funds_holding_enabled[pays]`.
