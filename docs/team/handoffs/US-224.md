## Décisions PROPOSÉ

- Codes `SETTLEMENT_SUPERSEDED`, `FIN_REVIEW_REQUIRED` (16 A.8 à compléter) ; alerte `FIN_SETTLEMENT_REVIEW` (P1).
- L'en-cours compte tout ordre non échoué (`PENDING`, `SUBMITTED`, `UNKNOWN`, `SUCCEEDED` non reporté) ; une réaffectation créditrice n'est disponible qu'une fois reportée (fail-closed).
- Un `LEG_RELEASE` d'un trip qui n'a aucun règlement reste admis à l'enregistrement (garde de 0054) ; dès qu'un règlement existe, la version en tête est exigée.
- `DEPOSIT_CAPTURE` exige aussi le montant dans la preuve signée (US-225 n'a encore aucun ordre).
- `COMME_TURO.md` : remboursement émis par Kmino sur le moyen d'origine, sans attendre l'hôte.

## Pièges

- `String.prototype.replace` interprète `$` : le générateur de la migration utilise `split/join` (comme US-223).
- La clé étrangère d'un ordre vers le trip pose un verrou partagé : sans le `FOR UPDATE` préalable de la commande, deux ordres concurrents s'interbloqueraient (40P01).
- Le canal d'alerte refuse tout identifiant d'objet : la référence du trip de N-13 (a) n'est jamais dans l'alerte, elle est rendue à l'appelant.
- `rueda/no-country-constants` s'applique aux tests d'`apps/api` : pays fictifs `XA` / `XB` et devise de test `XTS`.
- `core.autocrlf=true` : les fichiers modifiés par script gardent leur fin de ligne ; la migration est écrite en LF.
