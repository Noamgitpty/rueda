### Suites (à numéroter au BOARD par l'orchestrateur)

- **A — lecture des paramètres par l'API** : l'API résout encore les paramètres depuis `apps/api/src/modules/cfg/data/*.json` (US-013) ; une valeur changée par la commande vaut pour les commandes SQL qui la lisent, pas pour la résolution de l'API ni pour le contrôle de démarrage `PARAM_UNDECIDED`. Avant tout changement réel d'une valeur lue par l'API : lecture depuis la base (ou contrôle d'écart bloquant). Préalable de N-412 si `booking_request_mode_enabled` est lu par l'API.
- **B — bornes** : poser par migration revue les bornes des clés numériques à rendre modifiables (par pays, unités mineures), décision du fondateur ou défaut PROPOSÉ ; d'ici là elles restent refusées.
- **C — clés JSON** : schéma de validation par clé (barème du trip fee, grille de protection, parts) avant de les ouvrir à la commande.
- **D — écran US-535** : route de console, traduction HTTP des issues (`PARAM_INVALID_VALUE`, `PARAM_UNDECIDED`, `PARAM_RETROACTIVE`, `SELF_FORBIDDEN`, `ALREADY_PENDING`, `EXPIRED`…), textes es / en / fr / pt-BR, ajout de `ux` à l'entrée US-535 du registre.

### Complément de spécification à proposer (demande de fusion de specs séparée, revues architecture, sécurité, argent)

- **17 §2.3, matrice** : ligne `config.param_write` — « ADMIN : oui (demande ou approbation, jamais les deux) ; SUPERADMIN : oui (demande ou approbation, jamais les deux) ; par les seules commandes `cmd_request_param_change` / `cmd_approve_param_change`, deux personnes distinctes et sans conflit d'acteurs ; hors interrupteurs ».
- **17 §2.3, rôles SQL** : propriétaire NOLOGIN `cmd_param_owner` (commandes de changement de paramètre), dans la liste des propriétaires par famille.
- **17 §3.2 (CFG)** : entités `param_change_request` (id, clé, pays, valeur, devise, valid_from, motif, decision_ref, demandeur, échéance, approbateur, statut PENDING / APPLIED / REJECTED / EXPIRED / CANCELLED, une seule PENDING par clé et pays) et `param_bound` (clé, pays, min, max, source ; insertion seule).
- **17 §7.1** : une valeur numérique n'est modifiable qu'entre ses bornes ; sans borne, refus ; une clé JSON ne change que par migration revue.
- **16 A.8 (codes d'erreur)** : `PARAM_INVALID_VALUE` (valeur hors type, hors bornes ou d'une autre devise ; bornes absentes) ; issues `SELF_FORBIDDEN`, `ALREADY_PENDING`, `EXPIRED` de la commande.
- **16 ADM-014** : la double validation vaut pour toutes les clés (plus seulement les paramètres monétaires).
