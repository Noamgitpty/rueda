# Passation US-126 — CGU de l'hôte et conditions de l'hôte versionnées (2026-11-12, agent back-end, claude-opus-5-5)

Branche `story/US-126-cgu-hote`, worktree `../wt/US-126`, PR en brouillon. **Statut : EN REVUE.** Revues exigées (`review-requirements.json`, story US-126) : code, **sécurité** (`SECURITY DEFINER`, garde appelée par `catalog_cmd_owner`, consentement), ux (« Revue design : OUI ») ; **architecture** (`packages/db/`). Sécurité sur un autre modèle que l'auteur. Décision : ADR-100 (PROPOSÉ).

- **Fait** (critères de 19 US-126) :
  - **Critère 1** : CGU de l'hôte jamais acceptées, ou acceptées sous la plus haute version majeure en vigueur ⇒ `core.catalog_cmd_submit_listing` rend `TERMS_REACCEPT_REQUIRED` (HTTP 409), l'annonce reste `DRAFT` ; garde dans la commande (L1-PM-28), après les photos et avant l'activation ; prouvé en PA et PY. **Partiel** : la confirmation d'une réservation par l'hôte n'existe pas encore (lot 2) ; elle appellera `core.ctr_host_terms_required` (BOARD N-66).
  - **Critère 2** : `TOS_HOST` v1 BROUILLON commune, en es (fait foi), en, fr et pt-BR (DEC-FONDATEUR-18, Q-016) ; servie avec version, date (`validFrom`), langue et marqueur BROUILLON (`GET /legal/documents/TOS_HOST`, `GET /host/accounts/{orgId}/terms`) ; gabarit « à valider par l'avocat », aucune clause « definitiva e inapelable » (test L0).
  - **Critère 3** : `core.ctr_cmd_accept_host_terms` écrit un consentement `TOS_HOST` versionné : gabarit exact de la langue affichée, `platform.now()`, contexte `HOST_ONBOARDING` puis `REACCEPT`, pays du compte d'hôte, C2 retenues ; version affichée périmée ⇒ `TERMS_VERSION_CHANGED`, rien n'est écrit.
  - Portée = pays du compte d'hôte (document propre à un pays ⇒ réacceptation là seulement) ; IDOR (compte d'un autre ⇒ 404, aucune écriture) ; droits (`app_api` n'exécute ni la garde ni l'état interne ; `app_worker`, `app_anon` rien).
  - Écran A10 `/host` : bloc « Conditions de l'hôte » (version, date dans le fuseau du pays du compte, BROUILLON, lien vers le texte, case obligatoire jamais pré-cochée) ; page `/legal/TOS_HOST` : date d'entrée en vigueur, mention « traduction » hors de l'espagnol, retour vers `/host` ; quatre langues, e2e 360 et 390 px, axe-core.
  - Docs : ADR-100, README CTR, CAT et `@rueda/db`, GL-15 étendue à `TOS_HOST` (`GO_LIVE_CHECKLIST.md`, requête `GL15_DRAFTS`), `COMME_TURO.md` (2 lignes), BOARD (US-126, N-66, N-67), fragment de CHANGELOG, OpenAPI, matrice des routes, `api.md`, `modules.md`.
- **Reste** : 1. revues ; 2. `docs/architecture/schema.md` recopié du job « base de données » ; 3. N-66 (confirmation d'une réservation, US-118, US-123) ; 4. N-67 (reports dans `docs/specs/`) ; 5. textes définitifs publiés en v2 majeure par la console (OQ-BR-24, OQ-MK-01, GL-15).

  - **Numérotation** : migration **0070**, ADR-100, fixture **9975**, catalogue i18n **v19**, suites N-66 / N-67 pris sur `main` au push ; US-105 et US-119 travaillent en parallèle : la PR fusionnée en second renumérote (fichier, en-têtes, README, ADR, cette passation, `schema.md`).
  - Écart assumé à 19 (« version courante ») : seule une version **majeure** exige la réacceptation (16 LEG-001, mécanisme d'ADR-091).
