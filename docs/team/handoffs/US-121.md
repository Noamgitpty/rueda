# Passation US-121 — Blocs de contenu éditables (2026-11-11, agent full-stack, claude-opus-5-5)

Branche `story/US-121-blocs-contenu`, partie de `origin/main` (b5daeef), worktree `../wt/US-121`. **Statut : EN REVUE** (PR en brouillon). Revues exigées (`review-requirements.json`) : **code**, **sécurité**, **ux** (story) ; **architecture** et **sécurité** (`packages/db/`), sur un autre modèle que l'auteur. Décision : ADR-095 (PROPOSÉ).

- **Fait** (critères de 19 US-121 ; DEC-FONDATEUR-18 : quatre langues) :
  - **Critère 1, sans déploiement** : l'accueil (`apps/web/app/(app)/page.tsx`) lit `GET /brand/content` (`content-source.ts`, `WEB_BRAND_API_URL`, cache 30 s, délai 1,5 s) et remplace les 12 textes du registre `EDITABLE_BLOCKS` (`@rueda/i18n`) par le bloc publié dans la langue de la page. Rendu par `app/rich-text.tsx` en éléments React. Édition, publication, historique et retour arrière : commandes d'US-034, déjà journalisées.
  - **Critère 2, jamais un bloc vide** : un bloc absent dans la langue de la page fait afficher le **texte du catalogue livré dans cette langue** (PROPOSÉ, ADR-095 point 4 ; UX-58 et US-014 : une vue = une langue). L'API garde le repli `es` signalé de 17, que le site écarte. Signalement au back-office : `GET /console/content/gaps` (`brand.edit`, ADMIN de tous les pays) et bandeau d'attention dans la console (langues absentes, corps hors règles, clés hors registre).
  - **Critère 3, textes juridiques** : motif `LEGAL_BLOCK_KEY` (legal, terms, cgu, contract, privacy, cancellation, refund, insurance, policy… en es / en / fr / pt). L'API refuse (`CONTENT_KEY_FORBIDDEN`). La base refuse aussi, **journalise** la tentative (`CONTENT_KEY_REFUSED`) et n'écrit rien. Un CHECK de la table sert de filet (migration `0059_config_content_legal_keys`).
  - **Assainissement (HTML assaini)** : liste blanche côté serveur (`parseRichText`). Le corps devient un arbre fermé, `plain` (une ligne) ou `rich` (paragraphes, listes, gras, italique, liens internes). Lien externe ou `javascript:`, caractères de contrôle ou de direction, longueur : refusés (`CONTENT_MARKDOWN_FORBIDDEN`). L'API ne sert que l'arbre (`doc`), que le site revalide (`isRichDoc`). Aucun `dangerouslySetInnerHTML`. Clé hors registre : `CONTENT_KEY_NOT_EDITABLE` (code PROPOSÉ).
  - **CSP renforcée** : le site n'avait aucun en-tête de sécurité. `apps/web/security-headers.ts` (toutes les routes) : `default-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, `frame-ancestors 'none'`, `nosniff`, `X-Frame-Options: DENY`, Permissions-Policy.
  - Textes visibles en es, en, fr et pt (`common.brand.contentKeyNotEditable`, `backoffice.content.gaps.*`), `CATALOG_VERSION` = 11.

- **Pièges / hypothèses** :
  - Un test qui écrit un bloc doit utiliser une clé du registre. Les tests d'intégration injectent un registre (`BrandOptions.blocks`) avec des clés tirées au hasard, pour rester isolés sur la base partagée. `route-matrix.int.test.ts` passe à `home.hero.title`.
  - Une clé hors registre est refusée avant la base. Un rôle sans droit reçoit donc 422 plutôt que 403 sur une clé inconnue : même ordre qu'US-034 pour les corps invalides. Le registre est public (textes de l'accueil).
  - Le motif juridique SQL doit rester identique au motif TypeScript : la preuve L0 lit `editable-blocks.ts`.
  - PostgreSQL local non démarré : la CI fait foi (test:int, test:l0, schema.md).
