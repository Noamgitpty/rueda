# Passation US-114 — File d'ajout au catalogue véhicules (2026-11-12, agent back-end, claude-opus-5-5)

Branche `story/US-114-file-catalogue`, worktree `../wt/US-114`, PR #123 (brouillon). **Statut : EN REVUE** (première passe APPROUVÉE par les quatre revues ; seconde passe à venir). Revues exigées : code, architecture ; **sécurité recommandée** (console, `SECURITY DEFINER`, droits nouveaux de `catalog_cmd_owner`, revue de code US-050 n° 2). Décision : ADR-104 (PROPOSÉ). Numéros réservés : migration 0074, ADR-104, catalogue i18n v23, fixture 9988.

- **Fait** :
  - **Critère 1** : `catalog_cmd_create_vehicle` (corps de 0067) ouvre, pour un véhicule sans variante, la demande `catalog_addition_request` `OPEN` et son élément de la file `CATALOG_ADDITION` (mécanisme d'US-109, échéance `catalog_addition_sla_business_h` du pays) dans la même instruction ; `catalog_cmd_submit_listing` (corps de 0070) rend `CATALOG_ADDITION_PENDING` après les photos : l'annonce reste `DRAFT`.
  - **Critère 2** : console `support_staff_catalog_addition` / `support_staff_resolve_catalog_addition` (TOTP, permission de la file dans le pays de l'élément, élément pris en charge, ADMIN : sa portée) → fonctions de domaine `catalog_addition_detail` / `catalog_resolve_addition` (`catalog_cmd_owner`) : `MERGE`, `APPROVE` (variante `HOST_REQUEST` sous licence), `REJECT` (motif fermé) ; le véhicule reçoit `variant_id`, l'élément est clos, la décision journalisée, `catalog.addition_request.resolved` part par l'outbox ; NTF : `EVT_CATALOG_ADDITION_APPROVED` / `_REJECTED` vers l'hôte.
  - 16 ADM-036 : nouvelle demande de l'hôte après un refus (`CATALOG_REQUEST_DUPLICATE`, `CATALOG_ALREADY_LINKED`).
  - API : `POST /host/accounts/{orgId}/vehicles/{vehicleId}/catalog-request`, `catalogRequest` dans `GET …/vehicles`, `POST /console/queues/items/{id}/catalog-addition[/resolve]` (OpenAPI, matrice des routes, contrats).
  - Écrans : A10 (statut, échéance, motif, nouvelle demande) ; O01 (demande, variantes candidates, création, refus). Catalogue v23 (es, en, fr, pt-BR).
  - Docs : ADR-104, READMEs CAT, SUP, NTF, `@rueda/db`, `COMME_TURO.md` (3 lignes), CHANGELOG, inventaire des données personnelles, matrice d'autorisations, liste blanche `SECURITY DEFINER`.
- **Reste** :
  1. CI complète, puis les revues.
  2. `docs/architecture/schema.md` : recopier le document imprimé par le job « base de données » (`inventory.test.ts` échoue tant que ce n'est pas fait).
  3. Numérotation contiguë depuis la fusion d'US-125 (0073, catalogue v22) dans la branche.
  4. Reports de l'orchestrateur (demande de fusion sur `docs/specs/`) : voir ADR-104 « Limites et reports » (17 §3.2.3, §4.5, §8.1 ; 16 A.8 ; 10b §4.3).
- **Suites** (revues du 2026-11-12, MINEURS reportés) :
  - envoi NTF non éprouvé de bout en bout : seul `planDispatches` l'est, pas de test d'intégration du travailleur `ntf_dispatcher` avec l'outbox réelle (même dette que `payout.*`) ;
  - aucun test de concurrence (deux décisions sur le même élément ; décision et nouvelle demande simultanées) alors que l'ordre des verrous (élément, véhicule, demande) est argumenté dans 0074 ;
  - à la prochaine modification, factoriser les corps recopiés de `catalog_cmd_create_vehicle` et `catalog_cmd_submit_listing` ; restreindre l'`EXECUTE` de `support_enqueue_review` par file si un autre producteur l'obtient ;
  - avertir l'hôte dès la création de l'annonce d'un véhicule hors catalogue ; déplacer la mise au point sur la demande ouverte dans O01.
- **Seconde passe** (2026-11-12) : `CATALOG_VARIANT_EXISTS` voit les variantes communes ; plafond de trois refus et aucune redemande après `NOT_ELIGIBLE` (`CATALOG_REQUEST_NOT_ALLOWED`, L0 PA et PY) ; `CATALOG_ADDITION_REJECTED` à la soumission après un refus ; finition gardée ; commentaire de la garde corrigé ; UX : pas de formulaire après `NOT_ELIGIBLE`, aucune présélection de la carrosserie ni de la traction, confirmation avant un refus, « en cours » pour une variante ouverte (4 langues).
- **Prochaine commande exacte** : `gh pr checks 123 --repo Noamgitpty/rueda`, puis `gh run view <id> --log` pour le job « base de données ».
- **Pièges / hypothèses** :
  - Les tests L0 d'US-115 et d'US-126 soumettent désormais un véhicule rattaché au catalogue : sinon `CATALOG_ADDITION_PENDING` précède les gardes qu'ils éprouvent.
  - L'assistant d'A10 n'a pas encore de choix dans le catalogue (US-508) : tout véhicule saisi en texte ouvre une demande.
  - Une variante créée par l'ops vaut pour le seul pays de la demande (`market`) ; la clé naturelle de 0063 l'empêche d'être créée deux fois (`CATALOG_VARIANT_EXISTS` : la rapprocher).
  - PostgreSQL local non démarré : migration, L0 et `test:int` prouvés par la CI seulement.
