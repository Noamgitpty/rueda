## Suite — e2e A10 stable (2026-11-15, agent dev-web, claude-opus-5-5)

Branche `story/US-118-e2e-a10-stable`, worktree `../wt/fix-e2e-a10`. Échec intermittent de `host-listings.spec.ts` « A10 : changer le prix… » (main da4c5c78, run 43764792333, es ; PR #169, run 43768832767, pt), à 360 px.

- **Cause** (journaux des deux jobs, puis reproduction locale) : `toHaveAttribute('aria-invalid', 'true')` sur le prix après « 40.50 » reçoit un champ à `50,00`, sans erreur. L'envoi du prix `50,00` n'était jamais attendu : l'URL portait déjà `saved=1` (création de l'annonce) et `toHaveValue('50,00')` relisait la saisie elle-même ; `waitForLoadState('networkidle')` ne fait rien quand le document n'a pas changé. Quand l'action finit entre la saisie de `40.50` et le clic, React réinitialise le formulaire à la valeur relue (`50,00`) ; le clic renvoie `50,00`, accepté. Reproduit à coup sûr en retardant de 1,5 s les réponses POST (2 échecs sur 4 sans le correctif, 0 sur 4 avec).
- **Pas un défaut du site** : la saisie ambiguë est refusée côté serveur (`pricingOf` → `minorFromInput`, tests unitaires de `account/host-listings.test.ts`), avec ou sans hydratation : un envoi natif passe par la même action serveur. `goto` attend `load` (scripts exécutés) ; le motif « clic juste après `goto` » ne cause pas d'échec ici.
- **Correctif (tests seuls)** : `submitAndSettle(page, bouton)` dans `e2e/fixtures.ts` attend la réponse du serveur puis la levée d'`aria-busy` du bouton (rendu qui clôt l'action, même rendu que la réinitialisation). A10 : prix relu sur la carte ; `networkidle` retiré. Même motif corrigé ailleurs : dépôt de photo (compteur de la carte), préavis d'A06 (`host-calendar.spec.ts` : fin de l'envoi puis rechargement et relecture).
- **À signaler** : sans JavaScript, `/host` reste sur l'écran de chargement (`loading.tsx` : le contenu diffusé n'est révélé que par un script), donc aucun formulaire n'y est utilisable. Le refus serveur vaut pour un envoi natif avant l'hydratation, mais l'espace de l'hôte n'est pas utilisable sans JavaScript : à trancher (dev-web / ux), hors de cette PR.
