# Passation US-012 — Console interne : authentification forte, rôles et journal (2026-11-03, agent back-end, claude-opus-5-5)

Branche `story/US-012-console-interne`, worktree `.claude/worktrees/us-012-dev`, PR #49 (brouillon). **Statut : EN REVUE**. Revues exigées : code, **sécurité** (RLS, rôles, `SECURITY DEFINER`, cryptographie ; autre modèle que l'auteur), UX (Revue design : OUI), et architecture (`packages/db/`). Décision : ADR-062 (PROPOSÉ).

- **Fait** :
  - **Critère 1** (un rôle sans droit d'annulation plateforme reçoit un 403 journalisé) :
    - `core.iam_staff_cmd_manual_action` (0034) relit la session, la MFA, les rôles en cours, la matrice `iam_role_permission` et le pays du trip ;
    - un refus écrit `STAFF_FORBIDDEN` (motif `PERMISSION`, `COUNTRY_SCOPE` ou `SUBJECT_NOT_FOUND`) et rend `FORBIDDEN` ; SUP `POST /console/actions` répond alors 403 ;
    - un ADMIN ou un OPS autorisé reçoit `UNAVAILABLE` (journalisé) : la commande de domaine n'existe pas encore (US-208), et aucun changement d'état n'est simulé. `RECORD_CLAIM` est enregistré, avec idempotence par `request_id`.
  - **Critère 2** (un compte staff sans TOTP se voit refuser l'accès) :
    - une session naît `NONE` ;
    - `iam_staff_cmd_begin` rend `TOTP_NOT_ENROLLED` et journalise `STAFF_ACCESS_DENIED` ;
    - `StaffGuard` répond 403 `2FA_REQUIRED` ;
    - sous la RLS : 0 ligne ;
    - côté back-office : écran de refus seul.
  - **Preuves demandées** :
    - un rôle sans MFA ne fait rien (commandes, RLS, lecture du journal) ;
    - la portée pays est respectée ;
    - chaque action est journalisée, l'audit étant écrit **en dernier** et rattaché à `manual_action` ;
    - un compte suspendu perd tout : rôles finis, sessions révoquées `ADMIN`, facteur désactivé, RLS vide, console en 401 puis `NOT_STAFF`.
  - MFA (0033) :
    - TOTP RFC 6238 vérifié par l'API ; secret au coffre (port `TotpSecretVault`) ;
    - la base juge le pas (±1 à `platform.now()`, strictement croissant) ; chaque tentative est comptée sous verrou AVANT que le secret ne sorte (au plus 5, puis 15 min, preuve de concurrence L0) ; limiteur `/staff/*` par IP et par compte ;
    - session élevée bornée à 8 h dès l'élévation, même ouverte avant l'attribution du rôle ;
    - élévation sur preuve HMAC-SHA-256 (clé `core.iam_mfa_proof_key`, lisible par `iam_staff_owner` seulement) ;
    - enrôlement par code hors bande ; réinitialisation par un **autre** admin ; suspension.
  - Autorité sur un membre du staff : jamais soi-même ; `iam.staff_roles_write` sur tous les pays de la cible ; une cible ADMIN ou SUPERADMIN ne peut être visée que par un SUPERADMIN. `audit.read` : ADMIN et SUPERADMIN lisent tout, OPS et FINANCE leurs propres lignes, jamais d'IP.
  - **Reports** :
    - US-010 : `p_mfa_level` est refusé s'il ne vaut pas `NONE` ; session de staff : 8 h à l'ouverture si le rôle existe, et **8 h au plus à l'élévation** dans tous les cas ;
    - US-011 : RLS-18 réduite (`app.session_token_hash` exigé par `has_staff_role` et `staff_case_covers`, élévation sur preuve) ; `approved_by` fermé à `app_api` ; bris de glace de production hors application (procédure dans ADR-062) ;
    - ADR-056 : un appel = une instruction, en autocommit ;
    - US-009 : audit écrit en dernier.
  - Code :
    - `packages/db` : migrations 0033 et 0034 ; propriétaire `iam_staff_owner` (amorçage, `OWNER_ROLES`, liste blanche RLS-15 : 8 fonctions) ; fixtures 9650 ; `setSessionContext` à 7 paramètres ;
    - API : IAM `internal/staff/` (TOTP, preuve, coffre, magasin, service, garde, routes `/staff`) et SUP (`/console/actions`) ;
    - back-office : `app/console/` (connexion, enrôlement, code, refus, console), composants `@rueda/ui`, mandataire `/api` ;
    - i18n : 47 clés es / en / fr, `CATALOG_VERSION` 4.
  - Docs : ADR-062 ; `packages/db/README.md` ; `apps/api/src/modules/iam/AUTH.md` ; `apps/backoffice/README.md` ; `docs/ops/ENV_VARS.md` (`RUEDA_STAFF_MFA_PROOF_KEY`, `RUEDA_STAFF_TOTP_ISSUER`, `RUEDA_API_URL`).

  6. **Reports de la revue sécurité (tour 2, rapports b), sans changement de code dans cette PR** :
     - **ADR-062, phrase inexacte à corriger** : ADR-062 dit qu'une ligne d'audit ajoutée par `app_api` « se distingue par l'absence de `after.countries` ». C'est faux : `app_api` écrit `after` librement, donc une ligne forgée peut porter cette clé et elle est alors indiscernable d'une vraie. À reformuler au prochain passage sur ADR-062 (orchestrateur ou story qui ferme `api_insert`).
     - **Échéance de fermeture d'`api_insert`** (journal, 0021, US-009) : avant la création du **premier vrai compte staff**, en même temps que l'installation de la clé de preuve et du coffre (US-003). Pistes : rôle `app_staff`, ou commande d'audit `SECURITY DEFINER` dédiée.
     - **`RUEDA_API_TRUST_PROXY` et limiteurs, pour US-003** : derrière le mandataire `/api/*` du back-office, `request.ip` est l'IP du serveur Next tant que `RUEDA_API_TRUST_PROXY` n'est pas réglé sur le nombre exact de sauts. Tout le personnel partage alors les quotas par IP de `/staff/*` (120 / min, MFA 30 / 15 min), et un seul client qui martèle `/api/staff/*` rend la console indisponible (429). Réglé trop haut, `X-Forwarded-For` devient forgeable et contourne les limites par IP ; seuls le quota par compte et le verrou de la base restent. US-003 fixe la valeur exacte par environnement et la documente dans `docs/ops/ENV_VARS.md`.
