## Règles de jeu et rejouer

- Un test vert prouve que l'attaque est **bloquée**. Un défaut est prouvé par un `it.fails` documenté, nommé par son constat (`F-L2-ARG-nn`) ; son attaque est jouée par un test vert qui affirme qu'elle a bien eu lieu et note l'issue (une observation absente fait rougir l'`it.fails` : jamais un vert qui masque). Chaque `it.fails` juge le **signal attendu**, jamais l'issue brute, pour que le correctif proposé le fasse passer au vert : F-L2-ARG-02 et 03, chaque offre admise est refusée, masquée (texte relu différent) ou présente dans la file GRAY_MARKET ; F-L2-ARG-04, imputation (mouvement de jambe), gel de la jambe HOST ou écart FIN ; F-L2-ARG-01, gel refusé.
- Après chaque scénario : **invariant par jambe** (`invariantIn`, `apps/api/test/support/redteam-l2.ts`) : faits de chaque trip touché (`core.finance_trip_leg_facts`, US-217 : Σ capturé = Σ encaissé = Σ jambes des encaissements), puis **tous** les contrôles FIN du rapprochement nocturne (`runMoneyReconciliation`) et l'oracle C12 (`core.booking_production_oracle`) sur toute la base : 0 écart ; interrupteurs du pays relus fermés. Les attaques en base sont jouées dans une transaction annulée et l'invariant y est lu **après** l'attaque.
- Interrupteurs : ouverts seulement dans une transaction annulée, par la vraie procédure à deux personnes (US-125), tête d'audit puis verrou (ordre de `golive.ts`, copie du parcours doré US-221) ; aucun fonds de tiers ; aucun secret ; `platform.now()` (horloge virtuelle) ; aucune constante de pays (lint `rueda/no-country-constants`).
- Attendus : vecteurs de l'export des oracles (`@rueda/money/golden-vectors`) ; contre-exemples au prorata, plafond de crédit et chargeback en PYG calculés par l'oracle `docs/specs/tools/check_legs.py` (`python -I -X utf8`, méthode de TJ10c, `cascade`, `chargeback`) ; codes de 16 et des migrations ; jamais le code testé.

## Limites et non exécuté

- **Prorata par un adaptateur réel** : un connecteur qui recevrait des jambes explicites et ventilerait quand même au prorata n'est visible qu'au rapprochement des relevés du PSP (lot C, US-603) ; au lot 2, la garde est le contrat du port (capacité `SUPPORTS_PER_LEG_AMOUNTS` validée, inconnue = non), prouvé sur l'adaptateur FAKE.
- **Signature du webhook** : la base fait confiance au drapeau `signature_valid` posé par la réception de l'API (`payment_cmd_receive_webhook`, EXECUTE `app_api`) ; la vérification HMAC est prouvée par la red team du lot 0 (`concurrence-webhook.int.test.ts`).
- **POLL** sur un compte de bac à sable d'un environnement non productif reste une preuve (0116, ADR-088) ; jamais sur un compte LIVE.
- **L2-PM-17** non rejoué (voir le tableau) ; **annulation par le voyageur** : libre-service au lot 5, la double annulation est jouée entre deux agents OPS.
