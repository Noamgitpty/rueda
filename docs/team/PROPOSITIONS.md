# PROPOSITIONS — écarts entre le code et les spécifications

> Ouvert par US-038 (2026-11-04, agent back-end, claude-opus-5-5). Un agent de story ne modifie pas `docs/specs/` : chaque écart entre le code et une spécification y est **tranché** ici. Soit c'est un **bug du code** (corrigé dans la story s'il est petit, sinon tracé avec la story qui le corrigera), soit c'est une **spécification à mettre à jour**. Dans ce second cas, la proposition est **PROPOSÉE** et attend une demande de fusion de spécification revue (architecture, plus argent ou sécurité selon `docs/team/review-requirements.json`), portée par l'orchestrateur. Une ligne close reste pour la trace. Les reports déjà listés dans `docs/team/RESUME_HERE.md` (« Reports à faire dans `docs/specs/` ») ne sont pas recopiés.

Statuts : **CORRIGÉ** (dans le code, par la story citée) · **TRACÉ** (bug du code, correction confiée à la story citée) · **PROPOSÉ** (spécification à mettre à jour) · **CLOS** (pas un écart).
