# ADR-105 — Vérification individuelle de l'hôte : faits vérifiés du KYC, filtrage des sanctions, profil fiscal chiffré, activation gardée en base

- **Statut** : PROPOSÉ (US-123, agent back-end, claude-opus-5-5, 2026-11-12). Revues exigées : code, qa, architecture (`packages/db/`, ports `SanctionsScreener` et `TaxIdSealer`, port `IdentityProvider` étendu), **sécurité** (KYC, RLS, `SECURITY DEFINER`, garde d'activation, liaison de console), **argent** (sous-marchand, interrupteurs, profil fiscal), ux (« Revue design : OUI »), sur un autre modèle que l'auteur.
- **Sources** : 19 US-123 (critères 1 à 6 ; défauts d'OQ-P2P-01, OQ-P2P-07, OQ-PAY-09) ; 16 HST-049 / FIN-008 (parcours, états, erreurs), VER-028 (sanctions), A.8 ; 08 BR-ACC-06, BR-PAYOUT-05 ; 17 §0.1 (interrupteurs), §2.4 (KYC de l'hôte, règle d'activation), §3.2.1, §3.2.2, §4.5, §10 (`HOST_VERIFICATION_DECISION`) ; 10b A07, UX-40, §4.3 (`web.a07.waitingCountry`) ; BOARD N-28, N-38, N-66 ; ADR-026 / ADR-051 (clés par sujet), ADR-092 (actions de console), ADR-096 (compte d'hôte), ADR-100 (CGU de l'hôte), ADR-102 (KYC).

## Contexte

Le compte d'hôte existe (US-107, `ONBOARDING`), le KYC du voyageur aussi (US-105, sans date de naissance ni résidence), les CGU de l'hôte (US-126) et le sous-marchand du PSP en base (US-061). Rien ne vérifie l'hôte ni ne l'active ; les interrupteurs du pays valent `false` en production et ne changent que par la commande à deux personnes (US-125, en cours).

## Décision

1. **Faits vérifiés du KYC** (N-28, N-38) : le rappel signé du fournisseur d'identité porte, en plus des contrôles, la date de naissance lue sur la pièce et le pays de résidence (port `IdentityProvider` : `checks.subject`, lecture stricte). `core.kyc_cmd_decide_with_facts` appelle la commande de 0072 **inchangée** puis, si le rappel est appliqué, consigne ces deux champs (`core.kyc_identity_subject`, C2) dans la même instruction. **Règle de priorité** : la valeur vérifiée du dossier d'identité courant approuvé fait foi ; à défaut, la date **déclarée** du compte et le pays du **compte d'hôte**. Date inconnue : jamais « majeure » (`HOST_AGE_UNVERIFIED`). Résidence vérifiée différente du pays du compte d'hôte : refus (`HOST_RESIDENCE_MISMATCH`, PROPOSÉ). Le pays des documents juridiques (`ctr_account_country`, ADR-091) n'est pas changé ici.
2. **Dossier `core.kyc_host_verification`**, un par compte d'hôte, soumis par la personne de la session : refus sans écriture si le KYC n'est pas approuvé, l'âge est sous `host_min_age_years[pays]` (21, OQ-P2P-01) ou inconnu, la résidence diverge. Sinon, pièces manquantes : filtrage, profil fiscal (exigé si `p2p_host_requires_tax_id[pays]`, absent = exigé ; types admis = `config_country.host_tax_id_kinds`, donc le RUC seul au Paraguay), CGU de l'hôte (N-66). Incomplet : `DOCS_PENDING` ; complet : `IN_REVIEW` et file de revue `HOST_VERIFICATION` (US-109). Colonne `screening_hold` ajoutée (PROPOSÉ).
3. **Filtrage des sanctions** (VER-028) par le port `SanctionsScreener` : le prestataire reprend la **session d'identité déjà vérifiée** (aucun nom ni date ne sort de l'application) ; la base consigne la version des listes, le résultat et une référence **opaque** ; aucune entrée de liste n'est copiée (audit et événements : code seulement). Correspondance (potentielle ou confirmée) : retenue `screening_hold`, motif `HOST_SANCTIONS_HIT`, dossier jamais approuvable ; **rien n'est visible de l'hôte** : le statut, les pièces manquantes et les réponses (état, profil fiscal, soumission) sont calculés exactement comme pour un dossier propre, ce que prouvent un test L0 et un test de contrat qui comparent les deux parcours étape par étape. Restent hors de la portée de l'hôte : la durée de la revue (une correspondance peut la prolonger) et la décision finale (`REJECTED`). **Escalade** : élément de la file `HOST_VERIFICATION` et événement interne `kyc.host_screening.flagged` (ADMIN, codes seulement) ; revue humaine par l'action de console `HOST_SCREENING_REVIEW` (PROPOSÉE, permission `kyc.decide`, `decision` ∈ {CLEARED, CONFIRMED}, motif et audit ; lever une correspondance est réservé à l'ADMIN, l'OPS_AGENT peut la confirmer) : faux positif levé ⇒ nouveau filtrage CLEAR signé du relecteur, dossier rendu à la revue ; correspondance confirmée ⇒ dossier `REJECTED`. Production : aucun prestataire avant le choix du pays (bêta pilote : filtrage manuel par l'ops, US-108) ; le dossier reste incomplet.
4. **Profil fiscal** (FIN-008) chiffré par la **clé du sujet** `ORG:<compte d'hôte>` (enveloppe v1, AAD de la colonne) **avant** l'écriture, par le port `TaxIdSealer` ; la base ne voit jamais le numéro, l'audit seulement son type ; crypto-shredding par destruction de la clé. Personne morale refusée (`HOST_ENTITY_NOT_ALLOWED`, BR-ACC-06). Contrôle de forme général (chiffres, lettres, tirets) ; format **par pays** reporté (paramètre de configuration à créer, PROPOSÉ). Production : aucun coffre avant l'adaptateur KMS ⇒ 503 (fail-closed).
5. **Décision de l'ops** `HOST_VERIFICATION_DECISION` (cadre d'ADR-092, gestionnaire `kyc_cmd_owner`, `EXECUTE` à `iam_staff_owner`) : `APPROVED` revérifie KYC, âge, résidence, filtrage, profil fiscal, CGU, puis approuve et tente l'**activation** ; `REJECTED` refuse un dossier non décidé. Une décision `APPROVED` sur un dossier déjà approuvé est une nouvelle tentative d'activation : un blocage restant est un refus motivé (`HOST_PAYOUT_RAIL_UNAVAILABLE`, `INSURER_CONTRACT_INACTIVE`, `HOST_UNDER_AGE`…).
6. **Activation** (17 §2.4) : dossier `APPROVED`, âge revérifié (N-38), profil fiscal, CGU, sous-marchand `ACTIVE` chez le PSP sur un compte du pays, **toutes les capacités bloquantes** du PSP de ce compte `VALIDATED_*` (variante du compte ; inconnue = « non » ⇒ `PSP_CAPABILITY_MISSING`, contrainte 4), `p2p_private_hosts_enabled[pays]` **et** `insurer_contract_active[pays]` (lus par `core.config_go_live`, absent = false). Blocage : compte `PENDING_ACTIVATION` (fail-closed, critère 6). **Garde en base** en plus de la commande : la seule politique d'écriture du compte d'hôte (`kyc_cmd_host_update`) n'admet `ACTIVE` que si `core.kyc_host_activation_allowed` est vraie. Aucun interrupteur n'est écrit ici.
7. **Événements** (17 §4.5) : `kyc.host_verification.decided` ; `iam.organization.status_changed` à chaque changement ; `iam.organization.created` **une fois**, à la première activation (N-38).
8. **API** : `GET /host/accounts/{orgId}/verification`, `POST …/verification`, `POST …/verification/tax-profile` (compte d'un autre : 404). **Site** : écran A07 `/host/verification` (quatre langues, sans JavaScript requis).

## Écarts PROPOSÉS à reporter dans les spécifications

- 17 §3.2.2 : `host_verification` gagne `country_code`, `missing`, `reason_code`, `residence_verified`, `activated_at`, `row_version`, `screening_hold` ; `vehicle_title_checked` et `lender_consent_file_id` restent à US-124 ; `host_terms_consent_id` remplacé par la lecture de `ctr_host_terms_required` ; `sanctions_screening` gagne `host_verification_id`, `provider`, `request_key`, `match_ref` ; profil fiscal en table propre (`kyc_host_tax_profile`) au lieu de `organization.tax_id` (laissée NULL) ; nouvelle table `kyc_identity_subject`.

## Conséquences

- Le chemin `ACTIVE` est prouvé sur la base de test seulement : interrupteurs ouverts par la procédure à deux personnes d'US-125 dans une fenêtre d'horloge virtuelle lointaine, refermés à la fin ; capacités du FAKE validées dans cette seule fenêtre.
- `registerSubmerchant` n'est pas appelé par cette story : le consommateur `payment_command` de `kyc.host_verification.decided` (appel du port PSP `FAKE`, `payment_cmd_register_submerchant` puis `payment_cmd_record_submerchant_status`, nouvelle tentative d'activation) est proposé en story séparée ; la garde lit déjà `psp_submerchant.kyc_status`.
- Reports : revérification automatique de l'activation quand un interrupteur ou le sous-marchand change ; filtrage continu et à chaque changement de compte de versement (VER-009, PYO-001) ; nouvelle revue partielle d'un profil fiscal modifié après approbation ; libellés des types de numéro fiscal par pays (donnée CFG) ; format du numéro par pays ; écran de la décision dans la console (bouton générique de l'action aujourd'hui).
