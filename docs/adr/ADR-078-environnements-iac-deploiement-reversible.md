# ADR-078 — Environnements, infrastructure en code et déploiement réversible

- **Statut** : PROPOSÉ (US-003, agent back-end, 2026-11-04). Revues exigées : code ; **architecture** (story, `packages/db/`) ; **sécurité** (story, `.github/`, IaC, secrets, image sans FAKE), sur un autre modèle que l'auteur. À reporter dans 17 §6.1, §6.5 et §8.1 (orchestrateur).
- **Stories** : US-003 ; s'appuient dessus US-004 (sauvegardes hors compte, supervision), US-036 (ports des services du fournisseur, export), US-050 (protection de `main` et de l'environnement `production`), US-408 (rapport « go »). **Sources** : 19 US-003 ; 17 §6.1 (pile, arbre de décision de région), §6.4, §6.5 (environnements, FAKE interdits en production), §6.6, §10 NN10 ; 16 ADM-034 ; ADR-006 (AWS us-east-1, PROPOSÉ), ADR-037 (portabilité), ADR-050 (travailleur), ADR-070 (pile de développement) ; OPERATING_RULES §1, §2.

## Contexte

US-003 demande une préproduction identique à la production, des déploiements réversibles décrits en code, et la possibilité de changer d'hébergeur. Trois contraintes du projet pèsent sur la manière :

1. **Aucun compte** : le choix de l'hébergeur engage de l'argent, il revient au fondateur (F-02, ADR-006 / OQ-MK-09). Aucun agent ne crée de compte, ne déploie chez un fournisseur ni ne touche un secret. L'infrastructure doit donc être **prouvée sans fournisseur**.
2. **FAKE jamais actifs en production** (C19, 17 §6.5) : l'image de production ne doit pas les contenir, et il faut le prouver.
3. **Reports en attente** : `platform.deployment_env()` était une constante « production » (0028) qu'une préproduction ne pouvait pas changer sans remplacer la fonction hors migration (US-025, US-043 : jamais NULL) ; le travailleur sortait en 0 sans boucle (US-008, US-035) ; l'image devait garder `@rueda/i18n` hors de `node_modules` (US-021).

## Décision

1. **Environnement déclaré par la base (migration 0050).** Table `platform.environment_declaration` (une ligne au plus), écrite **une fois** par le job de déploiement sous `migrator` (`platform.declare_environment`), jamais modifiée ni effacée (trigger, TRUNCATE compris), illisible par les rôles applicatifs. `platform.declared_environment()` (SECURITY DEFINER sous `guard_owner`, RLS-15) la lit ; `platform.deployment_env()` = `COALESCE(platform.declared_environment(), 'production')` : base non déclarée ⇒ production, **jamais NULL**. Une base de production ne devient jamais autre chose (changer d'environnement = une autre base). La surcouche de développement d'US-035 déclare désormais `development` par la même fonction. Preuve : `l0-us003-environment` (base de production sous `app_api` et `app_worker` ; immutabilité par fixture 9910 dans une transaction annulée).
2. **Job de base du déploiement** (`packages/db/src/deploy/`) : refus hors `RUEDA_ENV` ∈ {preproduction, production} ; amorçage idempotent sous le rôle d'administration de l'instance, mots de passe des rôles de connexion, migrations sous `migrator`, déclaration, puis vérification sous `app_api` (rôle de production, environnement attendu, aucun compte PSP `FAKE`). Secrets lus dans l'environnement (injectés par le coffre), messages expurgés.
3. **Une image de production** (`docker/prod/Dockerfile`), trois commandes (API, travailleur, job de base). Base Node épinglée par empreinte ; dépendances de production seulement (`pnpm install --prod`), donc sans `@rueda/fake-adapters` ; liste blanche de copie ; harnais, surcouche de développement, tests et migrations de test retirés ; utilisateur `node` ; `RUEDA_ENV` non posée (absente ⇒ production) ; version (`RUEDA_RELEASE`, étiquette OCI). Les paquets TypeScript de l'espace de travail restent sous `/app/packages` (liens depuis `node_modules`) : Node 26 n'efface pas les types sous `node_modules`. Contrôles : `scripts/deploy/image-checks.sh`.
4. **Travailleur câblé** (`apps/api/src/worker.ts`, `worker-loop.ts`, `worker-tasks.ts`) : pool `app_worker` (rôle vérifié), garde C19 (`assertPaymentStartup`, revue code US-019), puis boucle : planificateur des périodiques, relais de l'outbox (borné), un lot par file, métriques ; arrêt propre sur SIGTERM ; sortie en 1 après 30 passages entièrement en échec. Tâches : `hold_expiry` (60 s), `disposition_sweeper` (période de CFG, une opération par transaction, reprise 40P01 ≤ 3), `booking_oracle` (24 h), `risk_pruner` (1 h, 90 jours), NTF (`ntf_dispatcher`, `ntf_sender` avec le plafond SMS du pays). Valeurs PROPOSÉES. Non câblés faute de port réel : `booking_conversion`, `payment_intent_sweeper` (PSP du lot C, US-061).
5. **Infrastructure en code : OpenTofu** (`infra/opentofu/`), fournisseur AWS épinglé (version exacte), module `environment` et deux racines (`preproduction`, `production`) : réseau à deux zones, PostgreSQL 16 géré (chiffré, TLS forcé, Multi-AZ et protection en production, mot de passe d'administration géré par le service), deux clés KMS avec rotation (`data`, `files`), deux compartiments S3 (actifs ; preuves et journal des déploiements sous verrouillage d'objet), coffre (contenants seulement, aucune valeur), registre d'images à étiquettes immuables, ECS Fargate (API derrière un répartiteur HTTPS TLS 1.2+, travailleur, définition du job de base), rôles d'exécution par tâche (chacun ne lit que ses secrets), rôle de déploiement par OIDC restreint au dépôt, au workflow `deploy.yml` sur `main` et à l'environnement GitHub (ADR-084). Invariants de production en `precondition` (refus du plan). **Preuve sans compte** : `tofu fmt`, `tofu validate` et `tofu test` avec un fournisseur simulé (`mock_provider`), job CI `infrastructure`.
6. **Déploiement réversible, même stratégie partout.** Image désignée par **empreinte**, jamais par étiquette ; job de base AVANT la bascule ; migrations **expand / contract** (une version N + 1 ne casse pas la version N), donc retour arrière **sans migration descendante** ; bascule gardée par la santé (API saine, travailleur en marche) ; **retour arrière automatique** si la nouvelle version n'est pas saine (local : script ; ECS : coupe-circuit avec `rollback`) ; **retour arrière manuel** = resservir l'empreinte précédente du journal. **Journal** JSON Lines en ajout seul (`scripts/deploy/journal.mjs`) : en cloud, un objet par ligne dans le compartiment des preuves (verrouillage d'objet) et dans le résumé du run.
7. **Préproduction locale** (`infra/local/compose.yaml`) : même topologie, **image de production**, `RUEDA_ENV=preproduction`, secrets tirés dans des volumes. Job CI `déploiement local` (`scripts/deploy/rehearsal.sh`) : image contrôlée ; déploiement ; route de webhook FAKE absente (404) ; refus C19 (API « production » sur cette base, `PSP_ADAPTER=FAKE`) ; redéclaration refusée ; version défectueuse ⇒ retour arrière automatique ; retour arrière manuel ; destruction puis reconstruction depuis le dépôt, sans autre action que les secrets. Le journal est un artefact du run.
8. **Pipeline** (`.github/workflows/deploy.yml`, manuel seulement, depuis `main`) : `build` (registre de préproduction) ; `deploy preproduction <empreinte>` ; `deploy production <empreinte>` refusé si cette empreinte n'a pas été déployée **avec succès** en préproduction par ce pipeline, puis soumis à l'**accord du fondateur** (environnement GitHub `production`, approbateur requis, **revérifié par le code** : [ADR-084](ADR-084-porte-de-deploiement-production.md)) ; la production reçoit la **même empreinte**, copiée du registre de préproduction ; `rollback` sans accord en préproduction, **avec** l'accord du fondateur en production (même porte, ADR-084 ; révision du 2026-11-04 après la revue sécurité, constat 4). Inactif tant que les variables des environnements GitHub n'existent pas (F-02) : la garde échoue sans rien toucher.
9. **`RUEDA_API_TRUST_PROXY` par environnement** : `1` en préproduction et en production (le répartiteur est le seul mandataire) ; absente en local et dans la pile de développement (pas de mandataire).

## Conséquences

- L'IaC est prête à être appliquée, mais rien n'est créé : le fondateur choisit l'hébergeur, la région, le budget et les comptes (QUESTIONS Q-007), puis suit `docs/ops/DEPLOY.md`. Le premier `apply` n'est vérifié que par simulation ; le pipeline ECS (`scripts/deploy/ecs.sh`) n'a jamais tourné contre un vrai compte (risque tracé).
- Le travailleur tourne dans la pile de développement : `smoke.sh` exige maintenant qu'il reste en marche (et non plus qu'il sorte en 0).
- Le nom de marque des messages est une variable (`RUEDA_BRAND_NAME`), pas une lecture du thème : le rôle `app_worker` ne lit pas la version de marque publiée (report vers US-120).
- Aucun canal de notification réel avant le lot C : `ntf_sender` échoue en `CHANNEL_UNAVAILABLE` ; les envois restent tracés.

## Limites et reports

- **Index partiels des balayages** (report d'US-025, ADR-068 « Limites ») : non faits dans cette PR ; à mesurer contre L0-04 (suite d'US-003, passation).
- **TLS vers la base gérée** : `PGSSLMODE=verify-full` ; l'autorité de certification d'Amazon RDS est dans l'image, épinglée, `NODE_EXTRA_CA_CERTS` posée (ADR-084, 2026-11-04) ; jamais exercée contre une vraie base.
- **Adaptateurs réels** des ports `FileStore`, `KeyWrapper`, `TotpSecretVault`, stockage des actifs de marque (KMS, S3, coffre) : US-036 ; d'ici là, l'API garde ses refus (fail-closed).
- **Sauvegardes hors compte et hors région, alertes, archivage des journaux 13 mois** : US-004.
- **Fichier de verrouillage du fournisseur** (`.terraform.lock.hcl`) : à produire par le fondateur au premier `tofu init` et à commiter ; en CI, la version exacte et la signature du registre font foi.
- **Protection de l'environnement GitHub `production`** (approbateur requis) et des branches : réglages du dépôt, US-050 / fondateur ; depuis ADR-084, leur absence fait échouer le pipeline (porte « accord du fondateur ») et le rôle AWS n'est assumable que par `deploy.yml` sur `main`.
- **Relais : événement empoisonné** (report d'US-008, revue code n° 4) : plafond et quarantaine non faits.

## Alternatives écartées

- **Terraform** : licence BSL ; OpenTofu (MPL 2.0) lit le même langage et propose `mock_provider` pour prouver sans compte.
- **`pnpm deploy`** pour l'image : copie les paquets de l'espace de travail sous `node_modules`, où Node 26 refuse d'effacer les types.
- **Constante d'environnement par surcouche SQL** (comme le développement) : une base de production pouvait recevoir par erreur une surcouche « preproduction » ; la déclaration unique et immuable l'interdit.
- **Migrations descendantes** pour le retour arrière : risquées sur des données réelles ; expand / contract garde la version N compatible.
- **Route `/health` dédiée** : nouvelle route publique hors matrice ; la sonde réutilise `GET /brand/content?locale=es` (publique, lit la base), déjà sonde de la pile locale.
