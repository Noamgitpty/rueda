# ADR-114 — Publication immédiate d'une annonce, retrait par l'hôte, revue de l'ops sur signal

- **Statut** : PROPOSÉ (US-118, agent back-end, claude-opus-5-5, 2026-11-13). Revues probables (`review-requirements.json`, story US-118) : code, architecture (`packages/db/`), **sécurité** (`SECURITY DEFINER`, RLS de `catalog_cmd_owner`, commande de console), ux, qa ; sécurité sur un autre modèle que l'auteur.
- **Sources** : 19 US-118 (critères 1 à 4) ; 16 HST-016 / HST-026, ADM-002 / ADM-003 ; 08 BR-LIST-08, BR-LIST-09, SM-2 ; 17 §0.1, §3.2.3, §7.2 ; 22 OQ-BR-29 ; **DEC-FONDATEUR-22** (« jamais plus lourd que Turo ») ; ADR-099, ADR-100, ADR-104, ADR-107 ; BOARD N-62 ; pré-mortem L1-PM-18, L1-PM-44.

## Contexte et écart assumé avec 19 et 16

19 US-118 s'intitule « publication d'une annonce **après revue de l'ops** » et 16 HST-016 prévoit une « revue manuelle de toutes les annonces au lancement ». Le fondateur a tranché le contraire (DEC-FONDATEUR-22, consigne du 2026-11-12, rappelée pour US-118) : comme chez Turo, **aucune revue systématique**. L'annonce est publiée dès que les contrôles automatiques passent ; l'ops n'intervient que sur un signal (signalement, risque, contestation) ou dans un pays qui l'exige par paramètre. Un véhicule hors catalogue ne bloque plus l'annonce (la demande d'ajout d'US-114 suit son cours). Ces écarts sont à reporter dans 19, 16 HST-016 / ADM-003 et 08 SM-2 par une demande de fusion revue (`docs/specs/` n'est pas modifié ici) ; ils sont inscrits dans `docs/team/COMME_TURO.md`.

## Décision

1. **Publication = la commande de soumission** (`core.catalog_cmd_submit_listing`, même signature, même route `POST …/listings/{id}/submit`). Sources SM-2 : `DRAFT`, `REJECTED` (correction puis nouvelle soumission), `UNLISTED` (remise en ligne) ; toute autre ⇒ `LISTING_TRANSITION_FORBIDDEN` (critère 1). Contrôles automatiques, dans l'ordre ; le premier en échec est rendu, l'annonce garde son état :
   1. photos ≥ `listing_min_photos` (`PHOTO_MIN_COUNT`) ;
   2. zone affichée sans adresse exacte (`LOCATION_AREA_ADDRESS`, point 3) ;
   3. CGU de l'hôte acceptées (`TERMS_REACCEPT_REQUIRED`, critère 3, US-126) ;
   4. compte d'hôte `ACTIVE` et `p2p_private_hosts_enabled[pays]` (`HOST_NOT_ACTIVATED`) : un compte n'est `ACTIVE` que si sa vérification (US-123) est `APPROVED`, garde en base de 0075 (critère 2, volet hôte) ;
   5. véhicule publiable (`core.catalog_vehicle_publishable`, US-124 ; critère 2, volet véhicule), motif rendu : `VEHICLE_ELIGIBILITY_REQUIRED` (déclarations de l'hôte pas encore faites), `VEHICLE_UNDER_REVIEW`, `VEHICLE_INELIGIBLE`, `VEHICLE_RELEASED`, ou la première règle stricte en échec (`VEHICLE_DOCUMENT_EXPIRED`…) ;
   6. `insurer_contract_active[pays]` (absent = false ; `INSURER_CONTRACT_INACTIVE`, BOARD N-62, 17 §0.1).

   Puis `listing_manual_review_required[pays]` (0085 ; `false` en PA et en PY, PROPOSÉ ; **absent ⇒ revue exigée**, fail-closed) : `false` ⇒ `LISTED` (`published_at`, journal `LISTING_PUBLISHED` motif `AUTO_CHECKS`) ; `true` ⇒ `PENDING_REVIEW` et élément de la file `LISTING` (sujet `LISTING`, échéance `listing_review_sla_h`). Issue de la commande : `LISTED` ou `PENDING_REVIEW` (au lieu de `DONE`) ; l'API rend `LISTING_PUBLISHED` ou `LISTING_SUBMITTED` avec le statut.

2. **Hors catalogue non bloquant** : la règle `CATALOG_ADDITION_PENDING` sort de `core.catalog_vehicle_blockers` (corps de 0077 recopié sans elle) et de la publication ; le véhicule devient `ELIGIBLE` avec la marque et le modèle saisis ; la demande d'ajout reste ouverte et l'ops la traite sans rien bloquer.
3. **Zone affichée (N-62)** : filtre **automatique** `core.catalog_area_label_is_address` (IMMUTABLE), jamais une revue humaine. Refusés : un nombre de trois chiffres ou plus ; une marque de numéro suivie d'un chiffre (« N° », « Nº », « n. », « nro », « núm », « # ») ; un mot de voie ou de logement suivi d'un numéro (calle, avenida, av., vía, carrera, street, rua, rue, pasaje, casa, apto, apartamento, depto, piso, lote, manzana, edificio, torre, local, oficina…) ; un angle de rues (« esquina », « esq. », « c/ »). Admis : « Barrio Norte », « Costa del Este », « Villa Morra », « Vía España », « Zona 1 ». Contrôlé à la création du lieu (`LOCATION_AREA_ADDRESS`, `fields` = `areaLabel`, message `common.listing.areaLooksLikeAddress` en quatre langues) **et** à la publication (lieu antérieur au filtre).
4. **Retrait par l'hôte** (`core.catalog_cmd_unlist_listing`, `POST …/listings/{id}/unlist`) : `LISTED` → `UNLISTED` ; suppression `UNLISTED` → `DELETED` ajoutée à `core.catalog_cmd_delete_listing`. L'une et l'autre refusées tant qu'une occupation `TRIP` ou `HOLD` du véhicule finit après `platform.now()` (`LISTING_HAS_FUTURE_TRIPS`, critère 4, OQ-BR-29 défaut fail-closed, BR-LIST-09 ; hold compris). Remise en ligne : la publication, avec les mêmes contrôles.
5. **Revue de l'ops sur une annonce en revue** (`core.support_staff_decide_listing`, `POST /console/queues/items/{id}/listing/decide`) : garde commune de la file `LISTING` d'US-124 (session, TOTP, permission `ops.review_listing_host` dans le pays, élément pris en charge, ADMIN : sa portée ; refus journalisés). `APPROVE` revérifie tous les contrôles des points 1.2 à 1.6 avec le titulaire du compte (16 HST-016 : contrat inactif ⇒ `INSURER_CONTRACT_INACTIVE`, l'annonce reste `PENDING_REVIEW`, l'élément reste ouvert ; autre motif ⇒ `LISTING_NOT_PUBLISHABLE` avec `values.reason`). `REJECT` exige un motif de la liste fermée `PHOTO_QUALITY`, `ADDRESS_VISIBLE`, `VEHICLE_MISMATCH`, `PROHIBITED_CONTENT` (PROPOSÉS ; sinon `DECISION_RATIONALE_REQUIRED`, 16 ADM-003). Décision : élément clos (`APPROVED` / `REJECTED`), journal de domaine (`LISTING_PUBLISHED` / `LISTING_REJECTED`, rôle de l'acteur, motif) et journal chaîné de la console (`LISTING_REVIEW_DECIDED`). La fonction de domaine `core.catalog_listing_decide` (catalog_cmd_owner, EXECUTE à iam_staff_owner seul) lit le statut et le titulaire du compte (`GRANT SELECT (id, holder_user_id, status)` sur `iam_organization`, politique `catalog_cmd_read`).
6. **Droits au plus juste** : `catalog_cmd_owner` gagne `UPDATE (published_at)` sur `catalog_listing`, la lecture des seules clés `listing_manual_review_required` et `insurer_contract_active` (politique `catalog_cmd_publish_read`), l'écriture au journal des seuls codes `LISTING_PUBLISHED`, `LISTING_UNLISTED`, `LISTING_REJECTED` (politique `catalog_cmd_publish_audit`). Aucun droit applicatif sur les tables ; `app_api` n'exécute ni le domaine de l'ops ni les aides internes ; `app_worker` et `app_anon` rien.

## Conséquences

- Preuves L0 PA / PY sous `app_api` (`l0-us118-listing-publication`), dans des transactions annulées où les interrupteurs ne s'ouvrent que par la procédure à deux personnes d'US-125 : chaque refus suivi de son témoin. Tests adaptés : `l0-us114` (la demande ne bloque plus), `l0-us124` (hors catalogue ⇒ ELIGIBLE), schémas `config-country`, `iam-schema`, `audit-schema`. Contrats `host-listings.contract`, `console.contract` ; e2e A10 ; matrice des routes.
- Aucun interrupteur n'est écrit hors d'une transaction de test annulée. En production, rien ne peut être publié tant que `p2p_private_hosts_enabled` et `insurer_contract_active` valent `false`.

## Limites et reports

- **Fusion avec la file** : `catalog_cmd_submit_listing` est aussi remplacée par US-108 (#132, 0081 : couverture du véhicule `VEHICLE_NOT_COVERED` et `INSURER_CONTRACT_INACTIVE`) et `catalog_vehicle_blockers` par le correctif VIN (#134, 0083). La PR fusionnée en dernier recopie les deux corps (même code `INSURER_CONTRACT_INACTIVE`, aucune contradiction).
- `listing_manual_review_required` absent ⇒ revue exigée : non écrivable en test (la garde de la configuration refuse une valeur nulle ou mal typée), prouvé par lecture du code comme pour US-124.
- Notifications `EVT_LISTING_APPROVED` / `EVT_LISTING_REJECTED` (16 ADM-003) : pas d'événement outbox ici (publication immédiate : l'hôte voit le résultat à l'écran) ; à ajouter avec le consommateur NTF si un pays active la revue.
- Retrait par la plateforme sur signal (`RESTRICTED`, `REMOVED_BY_PLATFORM` hors contestation N-61), fermeture d'une annonce `LISTED` dont le véhicule repasse non publiable (pièce expirée), modification d'un lieu existant : suites.
- Le filtre de la zone est une heuristique (PROPOSÉ) : un nom de quartier contenant un nombre de trois chiffres est refusé ; le message invite à n'écrire que le quartier.
